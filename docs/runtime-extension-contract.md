# 通用 Runtime 扩展契约提案

日期：2026-09-23。状态：**语义设计提案；已实施范围见当前接入契约，不是 wire schema**。

用途：支持任意应用持有自己的产品身份、上下文和工具，再调用 Caelis/Codex 完成受控执行。
产品归属见 [Bot 平台规划](bot-platform-architecture.md)。当前 Bot 内部端口见
[backend-contract.md](backend-contract.md)；[caelis-integration.md](caelis-integration.md) 记录当前固定公开协议。
新 Caelis wire 已完成隔离 Host 联调，真实模型待验；旧 Bot Mode 不要求兼容。
接口名称为语义占位，最终 wire 名称由各 Runtime 的公开协议定义，并在发布时固定版本。

## 1. 所有权

- 应用持有业务身份、产品数据库、工作意图和应用工具实现。
- Runtime 持有规范的 Session/Turn、模型执行、工具调用日志、审批、策略及恢复事实。
- 工具宿主持有其业务操作账本；以 native 调用 ID 幂等处理，不重复产生副作用。
- Bot 的个人资料、Notebook 和 Memory 跨 Runtime 共享，由应用按需提供；Runtime 的原生历史、
  凭据、授权和在途工作分别绑定。通用接口不得强迫应用按 Runtime 重建个人记忆空间。
- Runtime 只注册通用 client/application principal，不注册人设、宠物、提醒或 Notebook 产品类型。
- 各层有各自的事实源：应用的“希望开始”不等于 Runtime 已接受；Runtime 的工具调用成功
  不自动证明通知已送达、文件已导出或角色已移动。

## 2. 能力协商

握手返回协议版本、应用会话能力、工具传输、输入/产物限制、历史/事件恢复和平台约束。
按消费语义判断兼容，不维护 CLI release allowlist。缺少所需能力应返回结构化原因，
禁止回退成权限更宽的普通 coding session。

| 必需能力 | 应表达的语义 | 本轮状态 |
| --- | --- | --- |
| 应用会话作用域 | 创建/列出/恢复/关闭本应用拥有的会话；不可凭 ID 接管别的客户端 | Caelis 有身份与会话基础，需要核对/补齐统一应用作用域 |
| 显式执行配置 | role/context 版本、工具集、允许根目录、配置继承策略与固定模型选择 | 现有 Bot 专用组装需收敛成通用 profile |
| 应用工具绑定 | 受限 MCP 或 client-tool callback，真实调用归属、结果回传、取消与恢复 | Codex 已有 Bot MCP；Caelis 公开应用 callback 已接入 |
| 稳定操作与事件 | 幂等请求、精确 native target、接受/拒绝/未知、恢复查询和事件序列 | 复用现有原生能力，补组合验收，不能回退为文本推断 |
| 材料/成果 | 受控输入资源、执行侧文件访问、结构化成果和可读字节 | 两侧 Bot 交付路径未完整接通 |
| 历史与归档 | 分页、已结束工作保留、归档和删除语义分离 | 按各 provider 补足 Bot 所需连续性 |

不要求一个 release 发明新的全套 App Server。尽量在既有会话、权限、配置和恢复原语上扩展，
只补缺少的通用组合能力。Core 的自动测试应使用通用示例应用，证明没有依赖 Bot 目录或产品代码。

## 3. 应用会话配置

创建/恢复时使用一个持久、版本化的执行配置，至少包含：

| 字段语义 | 要求 |
| --- | --- |
| Owner | authenticated principal + application instance；由连接鉴权解析，不取模型参数 |
| Session purpose | 应用自己的角色标识/说明；Core 不硬编码 secretary、pet、reminder |
| Context/profile revision | 显式、可恢复的版本；记录每次激活生效版本 |
| Workspace policy | 允许的读取/写入根目录、执行与网络策略；必须经过宿主许可和 native 策略求交 |
| Configuration sources | 是否继承 CWD 指令、全局 MCP/技能、工作区 Memory 等；默认不隐式继承 |
| Application tool binding | 已登记工具目录/权限范围的引用；有版本、撤销和连接生存期 |
| Model/account selection | Runtime 管理的配置引用；不得要求应用转交原始密钥 |
| Memory binding | 可为空；普通 Workspace Memory 不因提供 CWD 自动进入应用私有会话 |

“由应用提供配置”不等于“应用声明什么权限就有什么权限”。Runtime 验证创建方有权使用根目录、
工具连接和策略；最终能力不得超出 native sandbox/approval 上限。

Bot 秘书以最小工具配置运行；专业工作由另一个配置启用任务所需执行能力。
普通 Caelis CLI/TUI 仍可使用自己的工作区策略。两种组装是通用的可选配置，
不是在 Agent SDK 中加入 `if Bot`，也不能将普通工作区目录伪装为全局个人 Memory。

配置升级只能在允许的静止边界显式生效并留下持久记录。进行中的 Turn 不变更已提交的工具 schema
或前缀。普通笔记/记忆更新通过读取和新消息进入上下文，不触发隐式 compaction。
如某 provider 不支持原会话升级，返回限制，由应用选择新执行绑定并保留旧记录。

## 4. 应用工具

### 工具目录

目录声明工具名、输入/输出 schema、版本、能力类别、必要策略和连接方式。
可发现只表示“有这个工具”；是否能执行由当前绑定和授权决定。
自动审批只能覆盖明确声明的应用内操作，不能扩大到任意同名 MCP、shell 或外部副作用。

传输允许两种实现：

- 私有、会话受限的 MCP 连接；不改用户全局配置，工作会话不得自动继承秘书连接。
- Runtime 发起的 client-tool callback；应用执行后返回带 native 调用 ID 的结果。

Codex 现有 Bot MCP 可继续使用。公开 App Server 也有 experimental `dynamicTools` /
`item/tool/call`，适合参考，不作为本轮必须迁移的稳定依赖。
见 [App Server 文档](https://learn.chatgpt.com/docs/app-server)。两种传输共享同一 Bot 工具实现，
不得为追求 wire 一致去依赖 Codex App 私有 IPC。

### 调用上下文

调用必须有可信绑定：Owner、native Session/Turn/item/call 标识、工具目录版本、激活/授权版本、
请求来源引用、截止时间与取消信号。授权使用协议提供或宿主签发且不可被模型替换的绑定。
不能根据模型参数里的 `userApproved: true`、`sessionId`、文件路径或引用的旧对话获得权限。

MCP 传输若不能携带原生来源，必须由每个会话独享的连接/能力令牌及 native 事件关联补足证据；
无法消除并发歧义时拒绝调用，不能把最近一条用户消息当作授权。
能力令牌只进入私有连接，不进入模型上下文、UI payload、普通日志或结果正文。

### 调用回执

请求 ID 在重连和重试时稳定。应用先登记 intent，再执行副作用，再登记结果；
相同 ID/相同参数返回原结果，相同 ID/不同参数冲突。调用结果包括确定成功、确定失败和未知。
断线不将未知改成失败，不自动再次操作外部系统。

Runtime 保留规范的 tool-call/result 历史；应用保留自己负责的效果回执。重连查询或重送相同调用
不得产生第二次任务、提醒或写入。取消必须说明“阻止新效果”与“已执行效果不可撤回”的差异。
必须连接的工具宿主不可用时，停止/拒绝需要它的激活，不能悄悄换成宽权限内置工具。

## 5. 工作执行与权限来源

通用操作覆盖 Create/Resume/Prompt/Steer（可选）/Cancel/Inspect/History/Archive；
响应保留原生 operation、run、turn 和 item 标识及终态。UI 只消费不透明产品句柄。

应用任务账本记录“用户目标 → 工作 → native binding → 结果”，不要复制出第二套互相竞争的会话状态。
完成报告应基于 native 终态和已登记成果，不能见到“Done”文字就结束工作。
应用恢复时先对账在途操作；创建结果未知时按同一 ID 查询，不再创建一个 worker。

输入来源至少区分原生接受的用户请求、授权的后台触发、应用摘要与外部材料。
后台触发可以使用通用的 source/grant 引用，不应要求 Caelis 认识 reminder 或 Bot schedule。
授权的产品含义由应用持有，Runtime 验证委托范围和自己的执行策略。
若 provider 仅能传文本，adapter 必须保留真实来源和限制，不能把模型生成的说明包装成用户的额外授权。

原生审批按准确目标路由，保留全部可选项和决定回执；不把一次审批转成全局许可。
专业工作可使用隔离目录，但目录隔离、文件读取上限、网络策略、OS 沙箱分别有验收，
不能以“创建了独立目录”代替权限隔离证明。

## 6. 文件与资源

输入与输出使用资源描述：不透明句柄、owner/binding、名称、MIME、长度、内容摘要和生命周期。
模型可使用受限资源引用，但不能指定归属、绕过校验或自行获得新的读取根目录。

本机可先通过显式允许的文件副本/共享目录实现，不要求首版支持远程文件服务。
协议仍要声明如何绑定执行、校验权限、读取结果；不能把绝对路径当成对外下载接口。
未来字节传输可以通过通用 upload/read 端口扩展，不增加 `bot/upload` 等业务 API。

成果登记必须限制为当前工作有权交付的内容，校验路径逃逸/符号链接及复制时变更。
产物快照形成后，任务即使归档仍可按保留策略取得文件；源文件消失应有明确错误或已有快照。
Runtime 不决定聊天卡片样式、用户“另存为”的目录，也不托管角色内容包。

## 7. 连接、租约与共享 Host

应用维护属于自己的会话和工具连接租约。断开桌面 UI、关闭聊天、隐藏宠物不撤销授权或中断工作。
明确退出、工具宿主丢失、租约过期和用户取消有不同状态，必须可查询。
重新连接只能恢复本应用的绑定，不接管其他 Caelis/Codex 客户端会话。

Bot 不能为了更新自己的组件强杀共享 Caelis Host。安装/更新与运行中服务版本分开报告，
需要重启时由 Runtime 官方生命周期能力处理并说明对在途工作的影响。
移除终端 Bot 不影响这些服务管理入口和普通模型登录/配置能力。

## 8. 替换与版本

新的应用扩展能力单独版本化。用户已授权移除 `bot-mode-v1` 及专用产品路径，
不要求迁移窗口、旧客户端兼容或旧 Bot 数据导入。普通 Caelis 会话、数据和凭据不得误删。
桌面客户端在新能力完整接入之前明确禁用 Caelis 执行，不调用旧模式或切到另一 Runtime。

当前 Bot Go 消费端已建立：

- `internal/backend/api/work.go`：原生工作执行与状态投影、受限应用报告输入；
- `internal/backend/api/application_tools.go`：应用工具目录与共享业务回调；
- `internal/backend/api/capabilities.go`：宿主注入角色和私有工具传输配置；
- `internal/tasks/manager.go`：产品 intent、目录、容量、账本和报告所有者。

这些是内部端口，不是新 wire schema，也不证明通用调用来源、资源和租约契约已经实现。
Caelis 侧需交付公开 schema/能力协商与 A01–A12 证据，再由 adapter 做语义映射。
不得通过私有 import、读取 Control SQLite 或直接解释旧数据目录来完成集成。

## 9. 必须具备的验收

| 场景 | 判定 |
| --- | --- |
| 通用客户端注入工具 | 无 Bot 包依赖；无全局配置变更；调用和结果进入正确的 native 会话历史 |
| 两应用/两会话并发 | 不能用对方句柄、工具绑定、资源或请求来源；重用 token/过期绑定失败 |
| 秘书与 worker | worker 不继承私人笔记/Memory/调度权限；普通 CWD 配置不能扩大秘书能力 |
| 切换 Runtime | 同一 Bot 的个人资料与记忆可继续使用；不复用旧 Runtime 的凭据/授权，不重复派发旧工作 |
| 回执丢失 | 同一调用/创建 ID 对账，副作用只有一次；未知保留且可恢复 |
| 连接掉线/租约撤销 | 不绕过缺失工具执行；UI 关闭不取消；显式撤销阻止新效果 |
| 权限路径 | 应用内委派不反复询问；真实外部写入仍按 native policy 审批；来源不可伪造 |
| 文件闭环 | 输入资源→隔离执行→结果登记→取回；越界、失效、尺寸超限和变更有确定行为 |
| 配置升级 | 在途 schema/前缀不变；静止边界升级可恢复；普通记忆更新不重写历史 |
| 旧模式退出 | 无旧 Bot fallback，不自动执行旧计划/报告；保留用户实际数据，不支持的新接口明确禁用 |
| 普通 Caelis 回归 | 原有 CLI、工作区 Memory、模型连接、MCP 和审批语义不因应用配置改变 |

Bot 侧再验收两套真实 Runtime 的同一产品流程。协议通过不等于原生 macOS、真实模型或 Windows
已经通过；这些证据单独记录在准备状态与联调记录中。
