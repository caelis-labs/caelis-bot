# Bot Control / Computer Use POC：MVP 与分阶段交付

2026-09-28 最新需求修订。**探索性 POC，已开始第一片实验实现，未承诺转为产品功能。**

后续优先级修正：**先上线 Bot 基础 Computer Use，角色控制不作为该能力的前置门槛。**
当前执行顺序与依赖选择见[依赖复核](computer-use-dependency-audit.md)：驱动/打包、真实模型闭环、正式启用分别验收。
下文角色 + 操作的完整场景与 POC-2/3/4 保留为后续探索，不再代表基础 Computer Use 的首发范围。

最新修正：组件语义、状态、动作引用和坐标是主路径，截图按需补充；第一片直接接入真实 Cua Driver。
当前实现/实测及限制见 [Cua Driver 验证记录](bot-control-poc-validation.md)。
本页替代此前“先做可玩的桌宠，再接模型”的交付顺序。语义协议见
[实验控制协议](bot-action-protocol-v1.md)，资产边界见 [最小资产交接](bot-action-assets-handoff-v1.md)。

## 1. 需要回答的核心问题

模型能否用少量、易懂的通用动作，一次提交短序列，由产品执行后反馈；
能否将用户的真实桌面理解为有窗口、目标和可活动区域的空间；
角色控制与真实 Computer Use 能否共用目标和结果，形成用户看得懂的任务闭环。

MVP 从“观察 → 模型批量计划 → 角色行动 + 一项真实应用操作 → 验证反馈”入手。
人工键盘/手柄只是可选调试输入，完整控制器映射、动作生态和游戏能力不作为前置条件。
只有核心链路与产品价值都验证后，才决定哪些部分转成正式 feature。

## 2. 最小的真实场景

用户说：“把当前页面切到只看未完成，并指给我看。”

1. 模型优先读取真实窗口的组件语义、状态、目标引用及坐标，结合工作区和角色位置识别筛选开关；结构不完整或需视觉确认时才补截图。
2. 一次提交 move 到目标附近、point 指向目标、click 操作目标的短序列。
3. 宿主使角色在真实桌面移动并指向；通过独立的 Computer Use adapter 点击同一个目标。
4. 宿主重新观察开关/列表变化，返回逐步结果与新观察；模型据此反馈完成或说明失败。

“同一个目标”必须由观察产生并绑定窗口/版本；角色表现和系统操作不能各自猜坐标。
角色附近的视觉动作不是点击授权，也不能代替开关确实变化的证据。
角色不能挡住目标、截获发给外部应用的点击或制造需要额外绕开的障碍。

先用可重置的真实浏览器页面/简单应用做验证，再在一个合适的实际工作场景复验。
可控页面是测试场景，不能据此宣称已经支持任意应用。不硬编码模型应当选择的目标与操作序列。
不要求复杂跨应用流程、持续录屏、完整桌面语义地图或实时游戏控制。

## 3. 提升优先级

| 能力 | POC 必须验证的内容 |
| --- | --- |
| 模型易懂的语义协议 | move、point 等通用操作，有限 steps 数组；jump 可作简单动作探针；没有按键编号或角色技能目录 |
| 桌面空间观察 | 当前显示器/工作区、目标窗口、角色位置、组件语义/状态/动作/坐标与来源/有效性；截图可选 |
| 原生身体执行 | 真实桌面位移、停止、边界与命中；动画消费真实运动状态，不只在 canvas 内跑步 |
| 本地序列执行 | 按顺序、按完成条件推进；逐步结果、超时、中断、旧目标失效与未知效果 |
| 模型尽早接入 | 第一片验证模型收到真实观察，第二片验证模型控制身体；无需等待完整角色资产 |
| 最小 Computer Use 联动 | 在 MVP 内完成一项可验证的真实点击/切换，复用身体控制的目标，不推迟到通用自动化平台建成 |
| 失败与接管 | 用户停止立即阻止后续派发；窗口移动/关闭、目标失效时重新观察，未知效果不重放 |

桌面几何可以复用当前 DesktopContext/placement，但其前台窗口不等于任务归属，也不等于已获得内容权限。
POC 新观察要补不透明目标、有效性与内容链路，不直接把 renderer 使用的原生窗口数字当作模型句柄。

## 4. 最小协议与联动方式

保留两个主要模型入口：desktop.observe 和 desktop.perform；名称为实验示意。
perform 接收一组有界语义操作，宿主负责路径插值、速度、动画、输入派发和逐步反馈。
中断复用宿主停止路径，必要时提供窄 cancel 操作；不要求模型维持方向键或逐帧心跳。

模型协议与底层执行分层：同一 move 对不同角色有一致的位移目标，
角色层决定走、滑动或其他表现；jump 表达一次有界跃起，角色决定动画。
姿态不支持时必须明确反馈，不能把“按钮有响应”当成满足 move/jump 的语义。

Computer Use 操作仍由自己的 adapter 执行，批量入口只统一编排、目标和回执。
许可按真实步骤判定；move 不授予 click 权限。只有常驻 Bot 获得产品模型工具，Worker 保持原生能力。

批量局限在有依据的短行动段。页面跳转、目标变化或外部效果需重新观察时，返回检查点与未执行步骤；
模型再规划后续。不是一次提交就盲目执行跨页面长脚本。
内部角色移动更新 actor 状态，不应让完全未变的 UI 目标失效；UI/窗口版本与角色状态分别记录。

## 5. 拆成独立 PR

以下保持为独立 PR 边界；本轮开始实验实现，尚未提交 PR。每片可独立测试、开关关闭和回退。

| PR | 交付 | 独立验收 | 不等待 |
| --- | --- | --- | --- |
| POC-1 驱动与结构化定位 | 默认关闭的真实 Cua Driver、语义目标/状态/坐标、Bot 专属观察/有限操作工具；截图作为辅助 | 真实组件定位→一项可逆操作→状态验证；过期引用拒绝；再补真实模型自主选择证据 | 手柄、动作包、角色位移与任意应用支持 |
| POC-2 模型批量控制身体 | move/point 的有限序列执行、真实位移、停止/逐步回执；最小角色适配，jump 按需要加入 | 模型从观察自主提交序列并使角色到达/指向；注入输入只验执行器，不替代真实模型验收 | 精修、第二个正式角色、社区导入 |
| POC-3 一项真实 Computer Use 联动 | 接可替换驱动的一项 click/切换操作、前后观察和目标重验 | 上述完整任务真实完成；角色位置与操作对象一致；界面变化可核对 | 通用浏览器平台、跨应用复杂流程 |
| POC-4 重复实验与去留结论 | 可重置场景、扰动用例、延迟/调用次数/失败证据、角色参与价值对照 | 给出继续/缩小/停止结论及应转正式的最小子集 | 不以“都做了”作为通过条件 |

POC-1/2 可用受控输入和假接收端独立测契约，但必须分别补真实模型和原生桌面证据。
私库若需最小运动修补，可与 POC-2 并行；现有角色/简单公开测试角色足以启动。
PR 合并不等于正式 feature 发布。实验默认关闭、不进入默认产品导航，不提前承诺稳定公共 schema。

## 6. 首轮范围与现有依赖

首轮锁定一台 macOS、一个显示器、一个角色、一种可用 Runtime、一个目标窗口与一种可逆应用操作。
一次只占用一个控制执行通道，不建设多 Agent 操控或多手柄路由。
跨平台接口从第一片保留；Windows 原生移植和双 Runtime 全量覆盖分别验证，不成为本次 POC 的同步门槛。

Caelis #81 由 [#82](https://github.com/caelis-labs/caelis/pull/82) 实现并已合并；
公开协议固定在合并提交 `369cd58b6d26cfd43057e0393fcab7d7c2c84cd8`。
独立 Review 不在本轮重复。需要 Caelis 多模态链路时按最终合入版本验收；另一个 Runtime 的实现不能自动算作 Caelis 通过。
首轮选择现有可验证的一个后端，不能借用开发助手自身的私有桌面能力冒充 Bot 已集成。

Bot 实验工具已接入结构化结果与可选图像内容块，桥接仍保留 10 秒 deadline 和 512 KiB 响应上限；
主观察链路不请求截图。辅助截图限制 256 KiB 原始图像，并使用 content-v1；不能把 Base64 文本当作视觉输入证明。
POC-2 先限制短序列以符合已验证时限；若需异步任务回执，窄范围增加按原调用查询/取消，
不重建一套工作任务平台，也不单纯提高 timeout 后丢掉执行状态。

## 7. 后置的工作

- 实体手柄/键盘产品模式、SDL 集成、完整标准手柄布局、系统虚拟 HID、游戏支持。
- 通用角色行为图、大量动作、角色特色表演、复杂道具/物理、自动重定向和高精度美术。
- 新公共资产格式、官方/社区包完整升级、创作者 SDK 与长期兼容承诺；POC 用内部最小适配。
- 多显示器迁移、复杂遮挡/路径规划、全桌面长期记忆、任意应用理解和所有平台能力对齐。
- 通用宏语言、分支/循环脚本、后台常驻推理、模型微调和控制技能训练体系。

用户手动操作或回放可用于定位缺陷，均非 MVP 产品完成条件。
POC 不扩大旧成品/导入合同；现有包照常使用，实验映射随实验代码撤销。

## 8. 开源复用与自建边界

复用现有原生位置/窗口服务、Three.js 和角色资源。
Computer Use 优先验证 Cua 等已调研的开源底座，只接当前场景所需的观察/定位/点击原语。
不因打包了 SDK 就宣称支持所有应用；Cua 官方
[能力限制](https://cua.ai/docs/reference/cua-driver/limits)对浏览器绑定和后台操作有具体边界，
必须按实际选定的窗口/驱动路线验证，不能默默切到另一个 profile 或应用环境。

仅自建小型语义序列执行器、公共目标/坐标转换与现有宿主适配，这是 Bot 的产品组合逻辑。
保留替换第三方驱动的接口；优先固定许可明确、维护成熟的版本，并检查驱动/包装/数据的全部许可。
source-available、付费 broker、退休底座不进入默认方案。协议设计不受某个库的字段和控制频率支配。

## 9. 何时才考虑转正式 feature

建议先锁定并运行以下实验，不宣称它们证明任意应用泛化：

- 固定真实场景至少重复 10 次，记录任务达成率、模型调用次数、执行时延和用户纠正次数；
  POC 继续门槛建议 9/10 达成，并在固定版本和失败记录上评估，不能挑成功片段。
- 单独覆盖窗口移动/缩放、目标关闭/失效、用户停止三类扰动；不得错点旧目标或虚报完成。
- 每次保留模型输入、步骤结果、原生位置与外部应用变化的必要证据；不在普通日志保存私人屏幕正文。
- 同任务比较角色参与与无角色操作：角色是否帮助用户理解对象、进度、结果，额外延迟/遮挡是否可接受。
  若只增加等待和动画，收缩到指向/引导等有用部分，不因为技术跑通就产品化。
- 确认能重复完成且有产品价值后，再单独确定正式范围：稳定 schema、资产导入、两种 Runtime、
  Windows 原生适配、长期恢复/性能、默认入口与文档。每项独立 PR，不一次承诺全部。

未达到门槛时允许停留在实验、缩小范围或删除 POC。
本轮仅安装独立实验目录的固定版本 Cua Driver SDK，未修改角色资产或生产依赖。Bot skill 仅在实验工具可用时加载对应指南；
后续实验工具用实验范围指导，转正式时再更新常驻 Bot 的正式能力说明。
