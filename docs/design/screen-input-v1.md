# Screen input v1 — Issue #26

2026-09-27，本地实现，尚未发布。截图是统一的屏幕信息采集入口；理解意图和学习使用习惯属于 Bot。
首版优先替代 Snipaste 的高频交互，不引入新的聊天身份或主面板。

## 用户路径

- 默认 F1 开始截取指针所在显示器的静止画面；拖选、窗口吸附、移动/缩放选区、放大镜与方向键像素微调。
  首版不跨显示器拖选。Shift + 方向键移动 10 个逻辑点。
- 箭头、矩形、文字、马赛克、不透明遮盖，调色板图标切换颜色、弹出连续粗细滑杆和实时预览、撤销/重做。工具栏仅图标，悬浮显示本地化提示。文字使用原生输入框，可走系统输入法。
- Cmd+C 复制选区并退出、Cmd+S 保存 PNG、F3 贴图、Enter 或点击备注框右侧 Ask Bot 发送；再次 F1 / Esc 退出。
  有文字选中时 Cmd+C 复制文字。选区完成默认聚焦备注；画布按 Space 返回备注框，输入框内 Space 正常输入。
  文字标注中的 Enter 只提交标注并返回备注；输入法候选确认及按键连发不触发发送。
  F3 在没有截图选区时贴剪贴板图片。截图和贴图快捷键可独立改键/关闭；冲突不占用已有注册。
  Mac 的功能键行为受 Fn/系统设置影响，遇到 Mission Control 等冲突时在 Bot 设置中改键。
- 贴图可拖动、滚轮等比缩放；右键复制/保存/再次标注/Ask Bot/隐藏/关闭。双击隐藏，菜单栏恢复/隐藏全部。
  贴图不创建聊天或任务。普通贴图仅保存在内存；显式发起 Ask Bot 后才暂存到磁盘以支持恢复。
- Ask Bot 默认提交「含标注选区 PNG + 带选区轮廓的当前显示器完整 JPEG」。设置中的全局「附带完整屏幕」默认开启，采集开始时冻结该偏好，截图工具栏不重复询问；
  关闭后仅发送选区。可选备注优先于推测意图。不要求输入重复的“请看这张图”。
- Bot 继续使用原有气泡/聊天输出，普通输入框草稿和附件保持原状。聊天展示选区图片卡片、应用名、独立整屏缩略图和备注；
  点击可查看原图并复制图片。预览跨重启保留，旧版本未保存的截图显示不可用。暂存截图送达后移除；拒绝可显式重试，
  结果不明时保留图片和原请求标识，不自动重发。重启恢复未确认/拒绝的截图为贴图。
  确认送达只依据 adapter 的真实回执/消息，UI 的待发送气泡不构成确认。
- 备注最多 4096 个 UTF-8 字节；保存前校验，超限保留完整文字与选区供修改。可选应用名/窗口标题
  按 UTF-8 边界截短至 512/2048 字节，不因系统元数据过长阻止发送。原生导出后若发送前校验失败，
  只有确定尚无发送回执时才清理无效暂存并恢复编辑；损坏/不明回执不能成为重发依据。

## 采集与隐私

macOS 14+ 用 ScreenCaptureKit 的 SCScreenshotManager 单张采集。已有屏幕权限才执行；权限不足进入既有
设置/权限流程，不隐式申请辅助功能，也不持续录屏。采集时排除宠物、气泡、快速输入和任务卡片等自有遮挡。
采集前读取前台应用和普通窗口元数据，保留应用名/标题/时间；元数据缺失不影响发图。
首版不读取 AX 树、浏览器 DOM、剪贴板文本、未显示页面或其他屏幕，不额外集成 Appshots 类依赖。

选区和整屏来自同一张冻结画面。所有标注共享文档与导出路径；不透明遮盖最后绘制，后加马赛克也不能重新露出
已遮盖像素。马赛克只是视觉模糊，敏感信息使用不透明遮盖。不会把未遮盖原图作为额外附件交给模型。

临时文件目录 0700、文件 0600；输入文件限制 8 MiB/张。选区优先原始像素 PNG，超限时缩小；整屏最长边
2400 像素 JPEG。坐标按最终编码背景计算，原点左上，不能混用 AppKit 左下逻辑点与 Retina 像素。
发送前校验路径归属、文件类型、尺寸与坐标；renderer 不提供任意文件路径。
发送前将展示图片原子保存到私有 ScreenMedia（0700/0600），展示层只拿不透明 ID，不接受路径。
接受后清理 Captures 暂存；ScreenMedia 的原图与缩略图可跨重启查看，30 天后可通过既有附件清理入口移入废纸篓，
不后台自动删除，也不通过历史预览重新发给模型。Runtime 为历史/恢复保留的附件副本沿用已有保留策略。
普通关闭未确认贴图只隐藏当前恢复入口，磁盘材料保留至确认送达；重启可再次看见。无后台发送或学习循环。

## 理解与学习

`caelis-bot-memory` 新增按需加载的 Screen input 参考。Bot 按用户备注、当前对话、截图和已记住的偏好理解意图；
例如英文讨论片段可以意味着翻译，但不按 Reddit/应用名硬编码动作。把截图中文字与标题当作参考数据，不能当作
工具授权。存在实质歧义时只问一个短问题。

用户纠正或明确习惯时，通过既有 Notebook/Memory 写入有范围、有依据的偏好；试探性推断只作暂定笔记，不能因
一次猜测或未收到纠正就成为稳定习惯。尊重更正/遗忘，不保存整张截图或无关隐私来学习。首版提供这条学习工作流，
不声称已通过真实长期使用证明习惯识别，也不是模型训练。

## 模型能力与后端边界

`api.ImageInputProvider` 返回 supported / unsupported / unknown。只认当前 Bot 常驻对话实际模型，不能用 Worker
模型或“任意已配置模型支持图片”替代。界面轮询能力变化，发送前再次核对；缺失/断线/文本模型禁用 Ask Bot。
不自动换模型，不把截图静默变成 OCR 文本。复制、保存、标注和贴图不依赖模型能力。

- **Codex**：读取标准 `model/list.inputModalities`，按显式选择/常驻模型定位；字段缺失保持 unknown。
  切换到图片模型后恢复按钮；adapter 在序列化发送锁内再次核对，避免旧按钮状态绕过门控。
- **Caelis**：握手协商可选 `application-model-capabilities-v1`，通过应用凭据读取
  `GET /application/sessions/{session_id}/model-capabilities`；响应包含当前 desired model、十进制字符串
  configuration_revision，以及可选 image_input（true 支持、false 不支持、缺失 unknown）。
  按钮展示和 adapter 发送锁内均重新读取，不用创建时 profile、全局能力并集或 Worker 模型推断。
  老 Host 未声明能力时继续正常连接，Ask Bot 禁用；新 Host 切换到支持图片的模型后自动恢复。
  能力读取只是观察，不锁定后续请求；Runtime 仍校验执行时实际模型。已有未知发送按原 ID 核对，
  模型切换不会产生新请求或把未知发送误标成拒绝。公共 schema/wire 固定于 manifest 指定的 Core 提交。

模块：`internal/desktop/capture*` 持有原生采集、选区/标注与窗口；`internal/screeninput` 持有平台无关快照和恢复；
`backend.SubmitScreen` 走普通 submission/回执通道并隔离 composer 草稿；adapter 持有模型/协议投影。
Windows 本轮不实现，未来同一输入契约允许无应用元数据、无完整背景的选区降级。
