## 设计决定

- 首次引导是一次按需出现的准备窗口。完成后关闭，回到桌面角色，不增加主仪表盘。
- 两个入口为「使用 Caelis」「使用 Codex」。借鉴登录入口的简洁感，但不把运行时说成账号。
- 设置页同时保留两个运行时的管理入口。「当前使用」负责切换；下方 Caelis／Codex 标签只切换管理视图，不改变当前执行后端。
- 对话、模型、工作、提醒、运行偏好、连接授权按运行时隔离；切换不导入、不合并、不迁移历史。角色外观、快捷键等产品偏好继续共享。
- Bot 调用官方安装和配置能力。运行时独立安装到用户本机，不放进 App Bundle 或 Bot 私有运行目录；卸载 Bot 不卸载运行时。
- 模型与账号凭据由运行时持有。Bot 不建立自己的密钥库，也不代管账号刷新。

## 首次启动

1. **选择运行时。** 可稍后设置；已存在有效选择和连接时跳过引导，直接恢复对应 Bot。
2. **准备运行时。** 自动发现 → 校验程序来源/架构 → 版本与协议能力检查。
   找到兼容安装就继续；未找到显示安装主按钮及「选择已有程序」。安装只在明确点击后进行。
3. **连接。** Caelis 复用已配置模型，否则展示模型配置；Codex 复用已有登录，否则打开官方登录。
4. **准备好了。** 原生连接、账号/模型可用性与 Bot 绑定都确认后才显示成功。默认不发送计费测试 prompt。
   点击「开始使用」收起引导、显示桌面角色。

### 检测与安装状态

| 状态 | 界面和行为 |
| --- | --- |
| 检测中 | 单行进度，保留返回；不把程序存在当作兼容或已登录 |
| 未安装 | 安装 + 选择已有程序；不要求小白先装 Node、Homebrew 或复制 shell |
| 不兼容 | 显示当前版本，提供更新或选择其他安装；兼容由协议/能力探测决定，不做精确版本白名单 |
| 安装中 | 下载、校验、安装、再次检测；展示阶段而非虚假百分比 |
| 下载失败 / 无权限 / 架构不支持 | 明确原因、重试或手动路径；保留已有安装和原连接 |
| 最新发行仍不兼容 | 停止循环安装，选择已有兼容构建、等待发行或选择另一运行时 |
| 服务未运行 | Caelis 使用官方 service start；不要求用户理解 Host，也不静默替换已运行的共享服务 |
| 安装完成但共享服务仍是旧版 | 单独提示版本差异；需要用户处理服务重启后重新检测，不把磁盘新版本当成服务新版本 |

Caelis 官方安装脚本当前默认安装至 `~/.local/bin` 并核验发行校验和。
Codex 官方现有独立安装器，首轮不强依赖 npm/Homebrew。Bot 原生服务复用官方流程、收集脱敏进度，
不自建升级器、不静默更新、不注入 shell 配置或擅自提权。路径按实际安装回执重新发现，不硬编码。

## Caelis：连接新模型

默认表单为「模型服务 → 认证 → 模型」。已配置的模型直接列出，避免重复填写密钥。

- API Key 服务：服务商、只写密钥、模型；服务地址和超时收进高级设置。
- 自定义兼容服务：服务地址与模型名提升为必填，不藏在高级设置中。
- 本地无认证服务：省略密钥字段。账号 OAuth 服务：使用该运行时原生登录能力，按能力显示；不能用文本提示冒充已登录。
- 模型、端点、认证方式等候选来自 Caelis `/connect` 的公共目录查询，不在 Bot 再维护一份服务商数据库。
- 提交前进行字段校验；调用 Caelis 配置接口后重新读取脱敏模型目录确认结果。
  如果配置接口只证明写入，界面不能声称真实模型调用已验证；付费连接测试需单独用户点击。
- Bot 表单中的密钥仅在提交时短暂传给原生桥接和 Caelis；成功、取消、离开页面即清空。
  不写 localStorage、偏好文件、日志、请求 journal、聊天、崩溃报告或埋点，不读回密钥。
  该表单是 Caelis 配置界面的 GUI 入口，凭据持久化和使用仍归 Caelis。

若后续要求密钥连 Bot 进程内存都不经过，需要由 Caelis 提供自己拥有的本机配置页，再从 Bot 打开。
这比“不由 Bot 保存/管理凭据”更严格，是另一种实现边界，不能靠隐藏密码框实现。

## Codex：登录与模型

- 已登录：读取运行时账号状态并继续，模型列表由 Codex 提供。
- 未登录：主按钮「使用 ChatGPT 登录」，由 App Server 发起 OAuth，浏览器完成授权；界面等待原生完成事件后再次读取账号。
- 登录中可取消、重新打开同一授权链接；失败或过期提供重试，不因浏览器关闭或 URL 返回就声称成功。
- 其他方式可使用 OpenAI API Key，经官方 `account/login/start` 交给 Codex 保存；Bot 仅作短暂传递。
- 不使用外部 token 注入模式，不让 Bot 承担 refresh。第三方自定义 Provider 只在 Codex 有可用公共能力时展示，不通过直接改私人配置文件伪装通用 GUI 支持。

## 设置中的长期管理

| 管理项 | Caelis | Codex |
| --- | --- | --- |
| 本机安装 | 检测、安装、版本、检查更新、显式更新 | 同等入口，使用官方方式 |
| 程序位置 | 自动发现、文件选择、手动绝对路径 | 同左 |
| 连接恢复 | 重新检测、原生服务启动、兼容性反馈 | 重新检测、标准 App Server 握手 |
| 模型 / 账号 | 已连接模型、连接新模型、设为使用模型、移除模型；认证方式按原生能力展示 | 登录、重新登录、API Key、退出登录、选择运行时提供的模型 |
| 高级管理 | 自定义数据目录、端点和参数 | 按公开能力展示，不能假设等同于 Caelis |
| 卸载 | 打开官方指引，说明数据归属；不随 Bot 卸载 | 同左 |

运行时管理不受「当前使用」限制：正在用 Codex，也能为 Caelis 添加模型，准备好后再切换。
移除模型或退出账号会影响共享该运行时配置的其他客户端，因此在执行时明确说明影响并确认。
当前使用的模型不能直接移除，先选择替代模型。运行时更新/重启同样不能自动打断其他客户端。

### 切换规则

- 就绪的新运行时：确认切换，持久化选择，激活它已有的独立身份；未创建身份时显式完成绑定。
- 尚未安装、未登录或无可用模型：进入该运行时的准备流程，原运行时仍可用；完成后再切换。
- 当前有运行、审批、未知回执或待交付结果：保持原连接，说明“先完成当前工作再切换”，提供返回对话或明确停止选项。
- 后台工作不因仅切换管理标签而取消。真正切换时撤销旧的 Bot 客户端激活，避免两个运行时同时发送提醒或驱动角色；不终止用户共享的运行时服务。
- 不在本轮引入跨运行时记忆同步、任务迁移、会话合并。切回时恢复各自历史、默认模型、草稿及授权状态。
- 第一实现可继续采用“下次启动生效”，但 UI 必须明确显示「待切换」并提供“重新启动并切换”；完成安全切换状态机后再取消重启。
  草稿演示的即时切换是目标体验，不是当前已实现的行为。

## 落地边界与切片

现有可复用入口：

- `internal/caelisruntime/runtime.go`：Caelis 检测、安装、更新、服务入口。
- `internal/backend/codex/auth.go`：Codex 官方登录开始/取消与回执处理。
- `internal/app/runtime_management.go`：provider 调度；`internal/backend/runtime.go`：选择与保存。
- `internal/backend/caelis/session.go`：Caelis 原生绑定；`settings.go`：已连接模型读取与 Bot 模型偏好。
- `protocol/caelis/openapi.json`：公共 `/completion/slash-arguments`、`/configuration/connect-model`、`/configuration/delete-model`。
  已有连接候选包括 `connect-provider-api-key`、`connect-baseurl:*`、`connect-model:*`，仍需逐项验证未创建 Bot 时的使用权限及返回语义。
- `docs/backend-contract.md`、`docs/caelis-integration.md`：后端能力、凭据与隔离约束。

建议按可独立提交的四片实现：

1. **设置视觉统一。** 共享控件尺寸、行内说明、可访问焦点、响应式；不改变运行时行为。
2. **独立 Setup 边界。** 增加用户操作专用的发现/安装/认证/配置能力，允许无模型时先准备运行时；不依赖先创建一个可执行的 Bot。
   使用类型化结果区分未安装、不兼容、未登录、无模型、权限不足和未知；高权限 Host 配置接口不能直接复用 Bot scoped token。
3. **首次引导与设置复用。** 同一状态机、双入口；接入 Caelis 模型目录/配置及 Codex 官方登录和安装；确保密钥不进入持久化操作日志。
4. **安全切换与隔离。** 新连接预检、旧连接工作保护、激活交接、失败回滚、各自草稿/会话恢复；覆盖退出与重启。

准备/配置服务不注册成模型工具。安装账号、更新凭据都是用户明确触发的管理操作，不能由 Bot 对话的自动审批代替。
macOS 首先实现，Setup 合同保持平台无关；Windows 后续适配其官方安装命令、路径发现与本机凭据/ACL，不让 renderer 执行 shell。

验收应覆盖：干净机器、已有兼容安装、旧版本、配置为空、登录取消/失败、网络失败、共享服务旧版、未完成任务切换、未知回执、重新启动、切回另一运行时。
草稿中的动画和成功文案仅用于体验评审，不替代这些真实状态证明。
