# 终端实例管理

2026-09-27：管理对象从精确窗口改为每张卡片启动的专属应用实例。基本体验为打开、
切到前台、关闭；折叠、快照和落点定位是可选增强，不承诺任意终端的全部能力。

## 身份与生命周期

- 标准路径先由 LaunchServices 创建新实例，再发送一次带回执的标准 Open Documents。
- 保存系统返回的应用句柄、PID 和出生标识；拒绝接管已有实例。
- 一张卡片管理该实例全部窗口。窗口数量、标题、TTY、session 不参与管理身份。
- Ghostty 原生创建是可选启动增强；控制层不包含终端品牌分支。
- 一次性脚本回执只证明连接命令开始执行。文档事件成功不代表脚本执行：有的终端
  在用户取消后仍回复成功。原生回复等待不阻塞主线程；回复后留三秒执行回执观察期，
  取消、应用退出或观察期结束时原子撤销未领取的脚本。只在撤销成功后允许新输入重试；
  并发领取的回执优先确认，不因未知结果补发。原生确认尚未结束时不积压打开请求。
- 回执客户端的 PID/出生标识独立于 GUI 实例。确认 TUI 客户端退出后，下次用户点击
  优先向原实例发送标准文档事件重连同一任务，窗口/标签页由终端选择。没有文档复用
  能力的适配器沿用解绑后新建的降级路径；未知客户端状态不算退出，不在后台自动重连。
  若旧客户端已退出的应用恰在复用时自行结束，旧脚本撤销成功且原应用确认退出后，
  本次点击可继续新建一次。存活应用里的取消不走此替换路径。
- 卡片关闭以标准 Quit 回执等待用户决定；等待时保留卡片，实际退出才移除。
  用户取消不算失败，恢复卡片操作。重复上滑不重复发起关闭；等待时点击卡片置前该实例。
  限时未确认保留卡片，不强杀、不报告成已关闭；Bot 退出可取消本地观察，不代替用户决定。
- Worker/Runtime 由原来的后端持有；关闭终端和取消 pin 都不是取消工作。

## 状态与命令

| 观察状态 | 点击行为 |
| --- | --- |
| 未创建或已确认退出 | 启动并置前 |
| TUI 客户端已确认退出、GUI 仍驻留 | 优先原实例重连并置前 |
| 打开请求已撤销且未执行 | 原实例重试；应用已退出则新建 |
| 原生打开确认尚未回复 | 保持打开目标，不发送另一个请求 |
| 前台 | 可折叠则折叠，否则保持前台 |
| 后台或已折叠 | 展开并置前 |
| 未知/查询失败 | 保留实例，报告限制，不重开 |

每个实例仍只有一个串行控制器。操作进行中再次点击只修改最终期望状态，不积压旧的
切换命令；显式用户输入优先，旧回调不能覆盖新状态。Show、Focus、Collapse 均为明确
方向，平台内部不得再次 toggle。接口返回不等于完成，随后以系统状态确认；限时结束
观察，不自动补发激活、抬升或启动命令。关闭同样等到实际退出。

macOS 使用标准 Activate Apple Event 一次展开并置前，NSRunningApplication hide 收起，
带回执的标准 Quit Apple Event 正常退出。等待回执在后台线程，不阻塞主线程。
不前置 unhide、不后补 raise 或反复激活；不需要辅助功能授权、精确 AX 窗口绑定或逐终端脚本。自定义 argv 启动未提供可证明归属的 GUI 实例时保持仅打开。

## 验证与边界

- Go 回归：合并快速点击、外部输入优先、未知结果不重开、关闭失败保留实例、
  已启动而未确认命令时保留实例、可选折叠/定位缺失不影响基本操作。
- 原生实例夹具：独立启动多个双窗口实例、归属隔离、PID 出生标识、隐藏、正常退出、
  退出后重新打开、连续三轮前台恢复。前台依据系统实际状态断言，不代替视觉动画验收。
- 真实本机终端：`make build` 后运行
  `bash script/build_and_run.sh --terminal-smoke iterm2 terminal ghostty`。
  仅执行临时脚本，不加载 Bot 数据、不附着真实会话、不调用模型。
  2026-09-27 16:30–16:31 三款终端各两轮完整通过，证据及视觉边界见 handoff。
- 手动确认专项：`bash script/build_and_run.sh --terminal-smoke --confirm-close terminal`，
  按提示第一次取消关闭，第二次确认关闭；只使用合成客户端。
- 打开取消专项：`bash script/build_and_run.sh --terminal-smoke --confirm-open iterm2`，
  第一次取消执行，第二次允许，验证同一实例收到新的连接回执；不修改终端安全设置。
- 截图仅是附加展示，存在多个可捕获窗口时允许占位。落点定位不支持时仍打开/置前。
- 手动关闭任务窗口后，即使仍有空白窗口或应用驻留，也按客户端进程退出证据重连；
  不按窗口数、标题或 TTY 猜测。新实例启动结果未知时仍不自动重试。
- Dock 图标、手动最小化后的完整恢复、多显示器/Spaces 和任意自定义终端不作为本轮保证。
- Windows 保留平台接口，不移植或承诺 macOS 的原生交互。
