## 1. 模型表达目标，宿主执行细节

模型使用 move、point、jump 这类朴素、跨角色含义稳定的动作；
一次输出有界 steps，宿主按顺序执行并返回结果。
模型不维持按键、不控制渲染帧、不认识特色技能槽位、骨架或动画目录。

同一 move 在不同角色上都表示身体到达指定空间目标；走路、滑动和相关姿态由角色适配层决定。
手柄/键盘以后可以作为额外输入来源，转换到相同执行器，不反过来决定模型 API。
OS 虚拟手柄属于未来的外部输入设备适配，不是角色控制协议的基础。

## 2. 小而完整的观察

desktop.observe 默认返回当前范围内的组件语义、状态、动作引用和结构化空间，截图按需补充，至少包含：
观察 ID、显示器逻辑坐标/工作区、目标窗口、actor 位置/朝向、有限目标及其来源/有效性。
目标可来自 Accessibility/浏览器结构化定位，也可由同一截图上的观察坐标建立；
缺失或不确定时明确返回，不凭空产生“可点击”能力。

统一目标引用连接三件事：模型看到的位置、角色要靠近/指向的位置、Computer Use 要操作的对象。
UI 目标带窗口代次、观察时间和定位证据；截图点带截图到桌面的变换。
模型不传裸窗口句柄或不带来源的绝对屏幕点。
当前桌面逻辑 +Y 向上，截图/不同平台坐标各自在宿主显式转换。
actor 状态变化与外部窗口/UI 修订独立，身体移动不自动使未变的 UI 引用失效。

## 3. 有限动作词汇

名称是实验提案，先实现主场景所需子集，不建立几十个通用工具：

| op | 固定意义 | 执行者与完成依据 |
| --- | --- | --- |
| move | 移动身体到空间目标，或某目标附近的安全落点 | 原生位置执行器；实际位置在容差内且停止 |
| point | 朝向并指示目标，保持短暂有界时间 | 角色执行器；朝向/指示效果完成，不改变任务状态 |
| jump | 一次有界跃起后回到支撑位置，可作为基本动作探针 | 角色执行器；落回并清理，不暗含点击或改变窗口 |
| click | 点击当前有效 UI 目标 | Computer Use adapter；记录派发并重观察实际效果 |
| type | 向明确的可输入目标填写文字 | 后续场景需要时才加入，不作为第一场景必需 |

move/point 是首片核心；jump 易独立验证，但不以复杂跳跃物理阻塞联动。
停止走宿主取消通道，能抢占整个序列，不是排在最后等待执行的普通步骤。
不支持的动作明确 unsupported，不能悄悄以点头代替移动或以播放动画代替点击。

角色适配只接收身体动作；Computer Use 操作由另一个执行器处理。
同一个批量入口不合并二者权限。角色数据与动画完成事件均不能发起系统操作。

## 4. 模型一次提交一个短行动段

模型入口建议为 desktop.observe 与 desktop.perform；均只供常驻 Bot 的实验能力发现。
以下是模型看到的精简请求示例，不是已实现 wire：

```json
{
  "observation": "obs-17",
  "steps": [
    { "op": "move", "target": "filter-open", "placement": "near" },
    { "op": "point", "target": "filter-open" },
    { "op": "click", "target": "filter-open" }
  ]
}
```

requestId、来源/调用、许可和执行代次由宿主或工具投影层附加，模型不用手工管理协议样板。
模型只带观察引用、动作与必要参数。输入使用有限 tagged union 校验，不接受任意脚本/代码。

首轮建议上限 8 步，整段时间预算由宿主发布且必须符合已验证工具传输时限。
宿主计算有界移动、插值、速度、朝向、动画与停止；完成回执驱动下一步，不用固定 sleep 猜测动作已经完成。
普通装饰性动作应短且可打断；不能为了“走到才能操作”引入不必要等待。

在准入时校验完整序列的字段/引用/上限，外部效果执行前再核验目标和许可。
实际执行不具有事务回滚语义，已发生的移动/点击不能因后续失败被报告成未执行。
同一执行请求只接受一次；按原身份查询回执，不用新 ID 重放未知效果。

## 5. 批量执行中的观察检查点

身体动作在当前有效空间内可连续执行。
click 等外部效果后重观察；页面跳转、焦点/窗口改变、目标失效或出现需判断的新状态时，停止当前行动段，
把已完成与未执行步骤返回模型。不要把旧截图上的后续点击静默带到新页面。

首轮将每项可能改变 UI 的操作作为观察检查点；如后面还有动作，返回待重新规划的剩余项，
不默认自动续跑。以后只有在明确的可验证前提下才允许更长的外部操作组合。
用户要求的批量效率通过一个稳定场景内的多步操作取得，不以跳过效果验证换取。

观察与准入共用目标引用，但效果验证需要新的证据。
宿主只确认它实际知道的事实；无法核对应用状态时返回 unknown/unverified，而不是“任务完成”。

## 6. 反馈、停止与恢复

工具结果以模型易读的短摘要、逐步状态、最终 actor 状态、最新观察及剩余步骤为主。
生产日志只保留必要元数据；图像和敏感内容继续走受控媒体路径。

- 每步区分 accepted/running/completed、failed、interrupted、unsupported、suppressed 与 unknown。
- click 的 inputDispatched 与 effectObserved 分开；派发回执不能证明开关/页面真的变化。
- 遇到失效目标返回 needs_observation；后续步骤为 not_run。保留前面已发生的事实。
- 用户停止、直接拖动、角色隐藏或实验禁用时停止身体执行并中止当前实验序列；后续动作不再派发。
  单独隐藏/停止不等于取消用户其他工作，当前实验序列的退出规则明确处理。
- 若取消时一个外部输入可能已经派发，记录 unknown 或已有确认事实，随后核对，不承诺撤销。
- 进程重启不恢复运行旧序列；保留必要回执，先观察。迟到 renderer 回报不能复活已停止执行。

同一时间只运行一个实验序列；控制来源与动作权限由宿主判定。Worker 不得到入口、凭据或实验指导。
状态/庆祝/指向都不能伪造 Runtime 工作完成与审批。

## 7. 桌面空间与角色适配

POC 采用显示器工作区 + 目标窗口/控件 + actor 的轻量空间，先单屏。
move 使用宿主计算的安全落点，避免覆盖目标；所有桌面位移归原生宿主，root motion 不独立推动窗口。
renderer 根据真实速度/位置播放局部姿态。气泡和命中跟随真实身体，不截获目标应用的点击。

先一个角色与内部最小映射：支持的动作、局部姿态/clip、最长时间、完成/中断和清理方式。
不能用角色分支改变公共 op 的意义；角色特殊配方不进入模型发现。
无需完整行为图、组合键系统、新成品合同或社区导入升级即可验证这一边界。
旧五 clip 与既有内容包照常加载；POC 映射只随实验代码存在。

## 8. 验证与将来演进

先测试目标/坐标、序列顺序、真实停止/完成、部分失败和过期引用，再让真实模型走同一执行链。
键盘/回放/合成 provider 是测试入口，分别说明证据范围，不替代真实模型与实际桌面效果。

版本先使用实验标记如 poc-1，不承诺稳定公开 schema。
固定实验动作含义并用回归样例保护；只在验证价值后抽出正式 schema、资产能力声明和兼容策略。
新动作仍须通用、可验证且许可明确；模型工具不随角色换装/换模型而改变。
