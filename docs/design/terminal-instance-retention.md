# 终端实例复用与闲置清理方案

2026-09-27：第一阶段标准实例复用已实现；第二阶段闲置自动清理仍是方案，不自动关闭用户现存终端。

## 问题与建议

此前客户端退出后，Launcher 释放旧实例句柄，再启动新实例。Terminal/iTerm2 的空白
窗口或无窗口 GUI 进程可能继续驻留；反复重连会增加 Dock 项。这不是 Worker 未退出，
也不能只靠隐藏 Dock 图标解决。

先从源头减少实例：**同一卡片优先复用同一个已确认归属的实例，重新打开连接文档；
只对有充分证据的闲置实例做正常退出。** 不往旧 shell 输入命令，不把“无输出”当成空闲。

## 第一阶段：通用复用

1. TUI 仍活着：沿用当前置前/收起，不再启动。
2. TUI 已确认退出而 GUI 仍活着：保留 PID/出生标识和应用句柄，通过 PID 定向的标准
   Open Documents 事件提交一次性连接脚本，确认新的客户端回执；不先冷启动另一个实例。
   这只请求应用打开文档，不保证终端一定新建窗口而非标签页。
3. 具备文档接口但明确拒绝时保留实例、提示能力限制，不自动换路径启动。没有文档接口的
   适配器沿用解绑后新建的降级路径。GUI 已退出时正常新建，复用仍经过同一串行控制器。
   打开取消或回复后未执行：原子撤销旧脚本后结束等待，允许下一次点击重试。
   事件回复成功不算客户端执行证据，未知状态不自动补发。
4. 保留实例后，卡片仍按当前产品约定管理该实例的整组窗口。用户在其中增加的工作窗口
   也会随整组收起；关闭仍走正常 Quit 和用户确认，不能声称自动区分每个窗口的用途。

Open Documents 是 macOS 标准事件，可用于支持文档打开的自定义终端；它不是“任意终端
新建窗口”的统一 API。需要以 Terminal/iTerm2/Ghostty 和明确拒绝的夹具验收。
Ghostty 已有冷启动增强保持可选，文档复用与基础控制层不包含品牌分支。

## 第二阶段：仅清理可证明闲置的实例（未实现）

| 证据 | 建议行为 |
| --- | --- |
| 实例已退出 | 释放管理记录 |
| Bot 客户端已退出，完整会话清单证明没有存活会话/作业，也没有未知窗口 | 对该 PID/出生标识发一次正常 Quit；确认退出后回收 |
| 适配层能证明剩余会话仅是 Bot 启动产生、未被用户使用的临时会话 | 可提供可选闲置清理；证据失效立即退回保留 |
| 有其他会话、用户新开窗口、后台作业，或用户取消过清理 | 保留，不周期性重复 Quit |
| 只有空白截图、shell 提示符、无近期输出、窗口数为零，或读状态失败 | 不足以授权自动清理；优先复用，无法复用则保留 |

完整会话清单是**可选能力**。AX 窗口枚举只能看到 UI；GUI 子进程树也可能漏掉独立会话
服务器/脱离的后台作业。两者不能单独证明应用没有工作。无法提供这项能力的终端不承诺
自动清理；不为实现它给每种终端建立复杂窗口匹配或强制安装 shell integration。

已有失去句柄的旧实例不按进程名、窗口标题或空白程度重新认领。不要批量退出同名终端。
正常 Quit 也不天然无损：有的应用不询问就关闭，所以**发 Quit 之前**就需要清理证据；
不能把二次确认当成安全兜底。若出现确认，等待用户决定，取消后停止这次清理。

## 验收重点

- 连续十次 TUI 退出/卡片重连，支持复用的终端只维持原专属实例，不持续新增 Dock 实例。
- 用户原先打开的同类应用实例始终不接管、不激活、不退出。
- 在专属实例额外开一个窗口并运行作业后，不自动 Quit；原 shell 内容不接收注入命令。
- 未知发送回执不补发；客户端只 attach 原 Worker，不重发任务 prompt。
- 清理取消保留实例和卡片；确认后按真实退出收尾；复用不影响现有整组切换。

## 接口依据

- [Apple Open Documents](https://developer.apple.com/documentation/coreservices/1527223-event_id_constants/kaeopendocuments)：向应用发送待打开文档列表，具体处理由应用负责。
- [iTerm2 scripting](https://iterm2.com/documentation-scripting.html)：`is processing` 仅表示近期收到输出；
  `is at shell prompt` 依赖 shell integration，均不能独立证明会话可以丢弃。
- [iTerm2 文档打开处理](https://raw.githubusercontent.com/gnachman/iTerm2/master/sources/AppKit/iTermApplicationDelegate.m)：运行脚本确认选择取消也可能返回处理成功，必须另查执行回执。
