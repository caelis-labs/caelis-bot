# POC 最小角色适配与后续资产交接

2026-09-28 最新范围。**本轮是探索 POC，未修改或发布角色资产。**
以 [POC MVP](bot-control-delivery-plan.md)和[语义动作协议](bot-action-protocol-v1.md)为准。
此前将完整手柄映射、公共导入和角色精修放在模型接入前的顺序已取消。

## 1. POC 只补核心链路缺口

模型调用 move、point、可选 jump，不认识角色配方、clip、骨骼或特色槽位。
相同 op 的外部意义一致，角色适配只决定如何表现，不决定是否产生 Computer Use 效果。
不再让模型通过猜按钮/组合来寻找动作。

优先复用现有角色、五段 clips 和局部程序化表现。只在核心动作无法可读地表达时，补必要片段或权重问题。
一个角色即可启动 POC；另用简单公开测试对象验证语义/位置不依赖私有骨架，无需先做第二个完整成品。

| POC 能力 | 最小角色工作 | 完成证据 |
| --- | --- | --- |
| move | 稳定支撑、简单移动/朝向反馈；按宿主实际位移同步 | 真实桌面位置到达；没有 root motion 和窗口各走一条轨迹 |
| point | 朝向/指示目标的可辨识姿态 | 目标明确、短暂保持、收回和可中断 |
| jump，可选探针 | 有界准备/跃起/落回，可用已有执行器做最小表现 | 回到支撑位置，命中/包围盒合理，停止时能收敛 |
| stop/隐藏 | 回落与临时资源清理 | 不续播旧动作，不改变任务/审批事实 |

不扩展大量表情、特色技能、道具物理、通用重定向或新的角色风格。
保持已验收的脸部、外观、授权和来源边界。运动明显不可读的缺陷要修，但精修不成为模型验证门槛。

## 2. 两个责任边界仍独立

公共 Bot 负责 op 的语义、原生位移、通用执行器、真实完成/中断和 Computer Use 联动。
角色作者负责姿态/clip、层与部位、包围盒、进入/主体/退出及本地表现映射。
角色数据不能点击外部应用、读文件、发送消息或产生执行授权。

POC 映射可先作为实验代码中的小型内部适配，不发布新公共 profile schema。
公共验收使用输入回放/简单对象和原生位置；制作验收使用连续画面，两者不能互相替代。
私库若有必要补片段，可与 POC-2 并行；不要求先搭建完整作者工具链。

## 3. 最小交接

交付必要片段或内部映射候选、动作时长/部位、边界、停止/回落说明、连续预览和未通过项目。
制作源与完整 provenance 留私库；公共仓库只消费许可明确的成品，不引入私库构建依赖。
旧成品/社区合同保持当前格式；需要新增文件/字段时先让公共消费者明确支持，不暗塞未识别数据。
本轮没有授权自动提交、推送或发行。

## 4. 只有 POC 有价值后再做

决定转正式 feature 后，才固定正式的输入/profile/executor 版本、公共 schema 与长期兼容。
届时官方成品和社区内容包分别升级封装、共用动作语义与正反例，补导入/切换/卸载/回退和公开制作示例。
多角色、无手/无脚角色与不同表达方式作为正式扩展验收，不作为第一轮探索的交付清单。

正式资产仍按公共消费者合入、私库锁定公开提交、导出验证、成品交付的顺序推进。
不要因为做出了候选动画就将全部动作规划转成产品能力。
