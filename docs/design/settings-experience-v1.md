# 设置与首次使用体验收敛

2026-09-28，本地实现，尚未发布。基于安装版 v0.4.0 的原生用户体验评估。

## 用户可见变化

设置从八个一级入口缩为五个，低频配置按需展开。

| 入口 | 默认展示 | 展开后展示 |
| --- | --- | --- |
| 常规 | 语言、四行快捷键摘要 | 快捷键编辑、存储、后台任务与终端偏好 |
| 外观 | 当前形象预览、形象选择、大小 | 聊天头像、扩展形象导入 |
| AI 与连接 | 当前连接、对话模型、账号或模型服务 | 工作模型、Team、服务管理和切换 |
| 隐私与权限 | 截图/通知权限、截图发送范围、执行授权 | 辅助功能/自动化权限、权限修复 |
| 关于与帮助 | 版本、更新、诊断报告 | 无独立诊断分类 |

- 权限显示系统事实和明确动作，不把 macOS 授权画成可以直接开关的应用偏好。
- 只有一种受支持的审批方式时展示说明，移除没有选择意义的下拉和保存按钮。
- 模型搜索保留固定面板高度，当前模型优先；推理强度与速度在参数展开区中，未修改时不可保存。
- 截图工具栏明确显示 Ask Bot 和本次是否附带整屏。单次选择不改全局偏好；已产生回执时锁定范围，
  未知结果继续使用原始回执核对。剪贴板图片不虚构背景图，恢复的截图按已保存的范围展示。

## 首次使用

顺序为「认识你的助手 → 可选权限 → 连接 AI」，三个步骤保持可见。
称呼仍通过已有初始化日志保存，作为普通用户消息交给 Bot，不新增身份配置源。
权限页只介绍截图和通知，可直接继续；连接页可稍后设置，再从 AI 与连接完成配置。
检测到已经可用的 Codex 时，保留明确的开始操作；默认不要求理解版本路径、模型参数或账户维护。
未知初始化回执不能重试派发；明确拒绝仍通过原来的显式恢复路径处理。

## 交互和资源使用

- 存储扫描与任务偏好在展开后才加载，权限查询仅在权限页展示时运行。
- AI 页返回时保留已读内容并刷新，执行配置的未保存草稿不会随分类切换丢失。
- 外观预览使用现有角色资源与静止姿势，只在加载和尺寸变化时绘制；关闭后释放 GPU 资源，
  不启动桌面事件、命中遮罩上传或持续动画循环。
- 快捷键录入显式获得焦点，Escape 取消录入，不同时关闭整个设置窗口。
- 小窗口中的模型面板给列表分配剩余空间，标题、搜索与底部动作保持稳定。

## PR #34：形象切换回归修复

原预览 effect 在切换模型时销毁 WebGL 上下文，却继续复用同一 canvas，导致第二个形象无法绘制。
现在每次 effect 都创建并拥有自己的 canvas，清理时一起断开观察、释放渲染资源并移除节点；
迟到的模型加载仍按原有取消标记释放，不写入下一次预览。React StrictMode 的 effect 重放遵循同一边界。

开发回归入口：运行 `npm run dev`，打开 `/character-preview-test.html`，点击 Run regression。
它使用生产 CharacterPreview、真实模型和 WebGL，仅在夹具中开启 preserveDrawingBuffer 供像素断言。
验证默认形象 → 简笔形象 → 默认形象的非透明像素、不同形象画面不同、切回画面一致、旧上下文释放，
再在 StrictMode 重跑。修复前已复现第二次预览上下文丢失，修复后八项结果全部通过。
这是通过 computer-use 运行的真实 GPU 回归，不作为常规 Node CI 已执行的测试；夹具不进入发布包。
证据为 `.cache/preview-fix-browser.txt` 与 `.cache/ux-screenshots/21-preview-context-before.png`、
`22-preview-context-after.png`。
最终修复通过 `make check/smoke/build`，日志 `.cache/preview-fix-{check,smoke,build}.log`；
构建产物中未包含开发回归页面。

此修复只调整预览渲染资源生命周期，不改变 Bot 能力、工具使用或恢复流程，因此无需追加 Bot skill。
