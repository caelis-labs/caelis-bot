# Weixin upstream compatibility review (2026-10-10)

Source of truth: Tencent's [protocol reference](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md), [channel](https://github.com/Tencent/openclaw-weixin/blob/main/src/channel.ts), [API wrapper](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/api.ts), [monitor](https://github.com/Tencent/openclaw-weixin/blob/main/src/monitor/monitor.ts), [QR flow](https://github.com/Tencent/openclaw-weixin/blob/main/src/auth/login-qr.ts), [text sender](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts) and [message dispatcher](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/process-message.ts). The inspected published `@tencent-weixin/openclaw-weixin` package and repository main both identify version `2.4.9`. This is a client implementation, not a complete service contract or a promise of independent-client support.

| Upstream behavior | Bot text POC compatibility |
| --- | --- |
| QR login, verification, redirect and bounded refresh | Go equivalent; QR auto-starts on settings entry, refreshes at expiry up to three codes while open, and retains manual retry. Account confirmation stays on the Mac. |
| `notifyStart` / `notifyStop` | Sent around the adapter lifetime, separately from message receipts. A successful notification is not proof that Weixin's phone UI reports online. |
| `getUpdates` long polling, cursor and `-14` session pause | Private atomic inbox/cursor and owner-only filtering remain. `-14` now persists a one-hour cooldown and resumes without re-pairing. |
| `sendMessage` with context token, client ID, finished state | Go text sender retains the outbound intent and attempt count before HTTP. The upstream wrapper accepts a successful JSON response with absent `ret`; Bot matches this while rejecting nonzero `ret`/`errcode`. At user request, unknown HTTP results get at most two further sends with the same client ID; backend deduplication is undocumented, so duplicate replies remain possible. |
| Text chunking | Upstream declares a 4,000-character OpenClaw chunk limit, but its normal reply path does not reliably apply a Markdown-safe chunker. The backend limit is not published; upstream [length rejection](https://github.com/Tencent/openclaw-weixin/issues/284) and [shorter delivery reports](https://github.com/Tencent/openclaw-weixin/issues/197) are observations, not a contract. A user-confirmed single message of 1,801 UTF-16 units / 4,559 UTF-8 bytes informs Bot's 2,400-unit and 6,000-byte client caps. Longer replies split at Markdown blocks and natural boundaries. Complete fenced code blocks stay together when they fit; larger fences close and reopen in each message. Each part has one durable intent and one-second pacing. |
| `getConfig` typing ticket and `sendTyping` | Ticket is fetched only for an active paired-user main turn, renewed after 24 hours, and typing is kept alive every five seconds until completion, approval, recovery or disconnect. Typing is disposable presentation state. |
| Block streaming and progress | The channel advertises OpenClaw block streaming (200-character / 3-second coalescing), not in-place text editing. Its structured tool progress items are OpenClaw runtime events. Bot currently sends final text and typing; partial text would require a separate prefix/revision/unknown-result design before enabling immutable intermediate messages. |
| Markdown filtering | Upstream strips selected unsupported markers. Bot keeps original final text for fidelity in this POC; copying that streaming state machine is not needed for transport compatibility and may silently remove content. |
| Quote cache, media, slash commands, routing and OpenClaw hooks | These depend on broader OpenClaw/Node capabilities or add new product surfaces. Direct owner text continues through Bot's existing natural-language and Worker path, with approvals on the Mac. |

The Weixin phone banner is a distinct backend signal. [An upstream report](https://github.com/Tencent/openclaw-weixin/issues/205) describes replies working while the phone says it cannot connect to OpenClaw, and [another report](https://github.com/Tencent/openclaw-weixin/issues/206) correlates that banner with intermittent long-poll failures. Adding the published lifecycle notifications closes a known adapter gap, but only a new user-side test can establish whether it changes this account's banner.
