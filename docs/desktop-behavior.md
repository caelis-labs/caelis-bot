# 桌面概念与助手交互基线

设计日期：2026-09-20。本文件为目标基线；首个实现切面已开始，完成范围和剩余项见第 7 节。
本文件细化[产品路线](roadmap.md)的 B（P4.2）。现有五段 clips、系统拖动和聊天入口继续保留。
阶段目标是开发者能够持续自用，以及真实运行的演示能看出情境动作、3D 朝向和独立道具的区别。
普通用户长期留存是后续研究，不作为当前探索和行为开发的前置门槛。

## 1. 最小桌面世界

早期就建立轻量实体/锚点数据，不等待复杂场景理解。一个可更新的快照和少量变化事件即可，
不需要语义地图、全桌面场景重建、物理引擎或完整窗口障碍图。

| 概念 | 最小数据 | 初期用途 / 边界 |
| --- | --- | --- |
| Desktop / Display | 逻辑屏幕边界、可用区域、显示器身份/比例、当前空间可用性 | 角色与道具的活动边界、休息点、越界回收；先验收当前显示器 |
| Dock | 所属显示器、可确认的边缘/区域、来源和 known/estimated/unknown 状态 | 作为避让区域或附近锚点；不读取每个图标、不操作 Dock |
| ActiveWindow | 前台应用/窗口的短期句柄、可取得的矩形、有效性与观察版本 | 角色可朝向它或避开它；只表示用户当前活动上下文，不代表 Agent 正在其中工作 |
| Pointer / Interaction | 鼠标位置、是否命中角色、悬停/按下/拖动/输入状态 | 局部注视、回应和动作让步；不采集键盘正文 |
| Actor | 稳定角色实例、当前位姿、休息锚点、可用动作 | Bot 的身体；独立于工作 Thread 和角色资产文件 |
| Prop | 道具实例、所属 Actor、局部/桌面坐标、运动与生命期 | 纸飞机等可脱离身体的对象；不自动成为第二个 Agent |

原生宿主提供 OS 观察，缺少的数据允许 unknown。Dock 的保留边距只能作为估计，不能将
屏幕可用区域之差说成精确 Dock 图标边界；自动隐藏或权限不足时用可用区域/安全边缘回退。
前台应用可知但窗口几何不可知时保留应用上下文，不伪造矩形或请求不必要的内容读取权限。
初期不读取窗口正文、不 OCR、不根据标题推测任务，不默认录屏。

每个对象记录来源、更新时间/版本与有效性；窗口关闭/句柄变化使旧锚点失效。显示器/Space
变化重新投影，不把不同坐标域拼成同一个矩形。所有运动使用统一逻辑点，渲染再换算局部坐标。
初期锚点只需 desktop.rest、desktop.safeEdge、dock.near、activeWindow.near；名称是语义示意，
未冻结为公开 API。near 保留空隙，不承诺站在窗口表面、碰撞或正确穿行在所有窗口前后。

**环境观察与任务关联分开。** Bot 可以因为用户切换窗口而转头，无需先把该窗口绑定到任务。
只有声称“我正在这个窗口工作”或把结果送到特定任务窗口时，才需要用户指定或可靠适配器证据。
复杂任务/窗口因果关联放在后续 C；基础 Desktop/Dock/ActiveWindow 和独立道具运动现在就设计。

## 2. 行为不等于单个 clip

一个行为由进入、保持/循环、退出、可中断点及可选道具提示点组成，可以复用骨骼 clip，
叠加有限头/身体转向。身体姿态、局部注视和道具轨迹分层；呼吸/注视不能覆盖主体动作的骨骼写入。
Profile 声明每层可用骨骼/遮罩和回退。当前小爱没有完整眼部/手指能力，先用头/身体表达，
纸飞机握持可用挂点，不以完整手指绑定作为启动条件。

### 待机初始基线：至少六套，四套安静、两套活跃

六套是本轮选定的初始设计值，用来替代未定的 X；可随实际小尺寸观感调整，不是用户指定的固定数量。
每套必须有可辨认的姿态或动作节奏差异，不能把同一 idle 改速度算成多套。原资产只有一个 idle；本轮以它和局部姿态层组合六种行为，尚未通过整体表现力验收。以下为行为工作名，最终 clip 名与人物会话对齐；原五段命名保持兼容。

| 行为 | 类别 | 表现方向 | 复用与资产需求 |
| --- | --- | --- | --- |
| idle_breathe | 安静 | 正常休息、轻呼吸 | 复用/修整现有 idle，作为安全回落 |
| idle_observe | 安静 | 头/肩缓慢朝向一个环境点，再回正 | 局部骨骼转向＋有限基础姿态；不持续追逐鼠标 |
| idle_weight_shift | 安静 | 换重心、轻微调整手臂姿态 | 新增与呼吸可区分的姿态，脚底稳定 |
| idle_plane_care | 安静 | 看看手边纸飞机、轻整理或托起 | 道具挂点与短动作；当前使用掌指关节的轻握姿态 |
| idle_stretch | 活跃 | 伸展/舒展身体，再回到休息 | 独立短动作，注意发饰、袖子与轮廓 |
| idle_plane_play | 活跃 | 抛出纸飞机、目光跟随，飞机绕行后返回 | 抛出/接回动作＋独立道具实体和轨迹；不能只在身体包围盒内摆动 |

空闲时本地随机轮换，默认安静组占较高权重；当前组权重为 70:30（从最初 85:15 调整）。
先筛选状态、能力与冷却，再随机；避免连续选同一套，在自然结束点切换，不能逐帧重新抽签。
安静行为可循环一段时间，活跃行为单次完成后回到安静组；首次活跃最早 18 秒，随后冷却 30–60 秒，
这些数值需在自用中调节，不作为硬协议。繁忙、输入、悬停/拖动、审批时不启动活跃待机。
概率只作用于过滤后的候选项，不等于活跃动作占全部播放时间的 30%。换重心现在由身体左右
移重、膝部补偿和头部反向倾斜共同完成；脚底保持在原有动画的支撑点。
开发预览允许指定动作/固定随机种子快速观看六套，但不把这种密集播放作为日常行为。

## 3. 交互矩阵

| 触发 | 角色/道具响应 | 保留的产品行为 |
| --- | --- | --- |
| 鼠标进入实际角色命中区 | 一次轻抬头/转向回应，随后有限注视；暂停新活跃待机 | 不主动弹输入、不抢焦点、不移动身体来躲开点击目标 |
| 鼠标停留 / 离开 | 短暂注视，停留不循环招手；离开平滑回到最新状态 | 不由每个 pointermove 重新触发动作；响应使用实际 mask，不用整块矩形 |
| 空闲单击 / 双击 | 简短局部触碰反馈；身体位置稳定 | 沿用单击输入胶囊、双击聊天；等待系统单双击分流，不额外发 prompt |
| 工作/待审批时单击 | 保留工作/等待主姿态，可叠加轻回应 | 沿用工作打开聊天、审批展开气泡，不因点击播放“完成”或批准 |
| 拖动开始 / 结束 | 中断活跃行为；当前 Caelis 按速度/方向展臂飞机跑、屈膝，停住或松手后平滑恢复 | Window Server 原生拖动优先，不能等待动画或新调度器；无可用骨架则保持原姿态 |
| 右键、输入与审批操作 | 安静保持，注视可停留于交互方向 | 菜单/编辑/审批不被表演遮挡、移动或抢焦点 |
| 工作开始 / 持续 | 至少两个工作表现：专注思考、观察/检查；局部变化低于空闲活跃组 | 状态来自后端事实，本地选姿态；不逐工具调用抖动切换，不假装一直操作某个应用 |
| 需要决定 / 到期提醒 | attention 一次，再保持等待；手势可配纸飞机提醒 | 待决定不反复催促；动画/道具不替代真实审批，提醒仍依赖原有常驻调度 |
| 工作完成 / 失败或中断 | 完成用有限 nod/celebrate 或交付动作；失败/中断回落并显示真实状态 | 不能用庆祝掩盖失败，不因动画未结束延迟真实结果 |
| 隐藏 / 减少动态效果 / 唤回 | 停止动态行为并回收离体道具；唤回从最新状态恢复，可短暂招呼 | 隐藏不取消工作，恢复不补播过期动作队列 |

优先级原则：系统可见性/减少动态效果和用户直接操控优先；真实审批优于装饰行为；
工作主状态不被 idle 替换，悬停回应可作为局部叠加。自发动作不得改变后台执行状态。
不监听键盘正文来判断用户是否专注；使用自身输入状态和可用的粗粒度交互事实，未知时保守。

## 4. 纸飞机是独立道具实体

道具属于角色的表现能力，但运行时具有自己的 transform、轨迹、边界和生命周期。
身体与纸飞机仍由同一 Bot 控制；飞机离开身体不创建 Thread，不继承执行/审批权限。
角色包可带多个数据资产：纸飞机可为独立 GLB，或可分离的命名子节点；两者均声明挂点与局部轴。

生命周期：stowed → preparing/held → flying → returning → stowed；任一步可取消并 cleanup。
默认空手，只有整理纸飞机与抛出准备时显示手中道具；普通待机、工作、交互和减少动态效果时不显示。
抛出动作在明确的释放提示点将道具从挂点转到桌面坐标，飞行完成、拒绝或取消后不立即在手里重生；
道具只有一个可见实例，禁止飞行时手里还留一个重复模型。早期用预设曲线、朝向和轻微倾斜，
不需要空气动力学、刚体碰撞或桌面障碍路径规划。

默认同一时间只允许一架短时离体飞机，轨迹限制在当前显示器可用区域，并尽量避开 Dock 和
活跃前台窗口的中心。无法安排合适路径时在角色附近短飞或跳过；无需理解窗口内容。
初期不跨屏、不无限游荡、不在桌面永久堆积道具。飞行中手动拖动角色时取消并收起飞机，
不追逐已移动的身体或回到旧挂点。隐藏/Space 切换/销毁或超时直接回收，恢复不补播。

默认道具全程点击穿透。若将来用飞机承载结果，只有明确的用户可见结果入口可交互；
结果关联使用原生 artifact 句柄，不让触碰飞机形成执行权限。
OS 表面由原生宿主管理；纸飞机不能被当前小尺寸角色窗口裁剪，也不能用巨大可点击矩形遮住桌面。
具体采用独立非激活道具表面或受控画布由最小原生实验决定，身体仍保留已验证的单窗拖动。
道具几何更新不经 LLM/每帧 Go RPC 往返，隐藏与销毁回收表面和 GPU 资源。

同一飞行动作可用于闲暇玩耍、用户明确请求、Agent 提醒/交付；意图与底层动作分离。
idle_plane_play 不含文件也不声称任务完成；用于交付时必须绑定真实结果。
普通自主行为本地运行，Agent 经受控动作接口发高层请求，并接收完成/中断/不支持等回执。

## 5. 框架最小切面

| 数据/职责 | 初期内容 |
| --- | --- |
| DesktopSnapshot | Desktop、Dock、ActiveWindow、Pointer 及版本/有效性；少量更新事件 |
| BehaviorProfile | 六套待机分组、权重、冷却、进入/退出、可中断点、骨骼层与需要的能力 |
| InteractionState | hover、press、drag、input、visibility，与独立 backend activity 组合 |
| Actor / Prop instances | 身体、挂点、独立道具、父子关系和 local/desktop 坐标；不等于原生窗口数量 |
| Action / Receipt | 高层意图、来源/目标、deadline、执行身份、完成/中断/失败/回退结果 |
| Local Director | 条件选择、有限随机与优先级；下发姿态和道具计划，不安排 Agent 工作 |

以上是内部设计词汇，待首个切面落地后固定类型；不先做公共 SDK、通用 ECS 或脚本插件引擎。
AppKit 负责原生观察/表面/输入，Go 拥有宿主实体生命周期与控制边界。道具轨迹由本地执行器推进：
需要移动 OS 表面时由原生执行器完成，Three.js 负责表面内的运动、朝向与身体局部动作；
renderer 不取得原生窗口所有权。Agent 后端保持独立，不为悬停、待机轮换或飞行动画持续推理。

## 6. 开发者自用与演示验收

先交付一个完整可运行的 B：轻量桌面骨架＋六套待机调度＋鼠标互动/工作切换＋一架离体纸飞机。
工程上可以分步合入，不能因只完成 head turn 就把整个 B 标为完成。

- 自用：开发者可跨多个工作时段保留角色，输入/拖动/审批正常；重复动作可接受，资源没有持续增长，
  不需要定期手工重启。记录实际观察时长和问题，不用固定天数或普通用户留存调查阻塞探索。
- 演示：真实桌面连续展示安静/活跃待机、鼠标回应、工作状态变化、飞机离体绕行并返回。
  至少能看出方向变化、身体与道具分离、交互触发的因果；不能仅展示逐个播放 clip 的模型预览器。
- 演示可加速动作触发，但使用同一运行时和真实动作路径。合成事件明确标为演示，不能伪造真实任务/审批。
- 只专项验证不确定的输入/表面/命中、姿态衔接与道具回收；稳定后端协议沿用既有检查。
  当前目标是开发者自用和有辨识度的演示，不将市场竞争力或长期用户留存提前标记为已证实。


## 7. 首个实现切面（2026-09-20）

已接入 Desktop/Display、估计 Dock、前台应用及可取得的窗口几何、实际 mask 悬停、输入/
菜单/拖动状态；未读取屏幕内容。六套行为由原 clip＋姿态组合，实现随机/冷却/让步、工作
focus/inspect 变化、有限注视和触碰回应。动作优先追求自然轻盈：400 ms 平滑混合、头先
身后、不同骨骼响应时间；不靠播放加速，不重复制作人物或优先增加面数。

原人物源文件和 GLB 保留；新飞机源资产/可重复导出脚本单独纳入仓库。飞机有独立的
非激活透明点击穿透表面，局部曲线绕行、目光跟随、单实例关联 ID 和完成/中断/超时回执。
7.5 秒完成，10 秒宿主回收；隐藏、Space/显示器变化、拖动或输入等立即取消。正常情况下
回到释放附近挂点；拖动期间采用取消回挂，不声称已有追踪新挂点的自然接回。

仍待推进：抛出/接回的精细手臂动作与朝向连续性、前台窗口中心避让、Agent 提醒/交付复用
飞机的语义请求/回执、更多角色的 profile/能力回退，以及开发者跨工作时段自用和真实演示。
当前只检查了关键运动/生命周期和原生路径，不宣称 B 完整验收或所有姿态均已自然流畅。

开发预览用 `CAELIS_BOT_BEHAVIOR_PREVIEW=1 ./script/build_and_run.sh --verify`：仅该进程的
应用主菜单增加开发动作入口，角色右键和状态栏菜单始终保持精简；常规启动不出现。此入口只演示
本地行为，不模拟真实任务完成或审批。关闭菜单后触发，用户互动仍可中断动作。

## 8. 眼嘴表情层（2026-09-20 增量）

表情层独立于骨骼姿态，以标准 morph targets 复用原面部几何；在身体 clip/姿态更新后、
绘制和动态命中 mask 前统一应用。无需新的 Agent 推理或 native 高频消息。

| 场景 | 眼睛与嘴巴 |
| --- | --- |
| 常态 | 3.2–7 秒的有限随机眨眼间隔，闭合快、打开稍慢，左右略错开；嘴部保持轻微微笑 |
| 鼠标进入 / 点击 | 进入时短暂暖化嘴形并就近眨眼；点击提供短笑回应，实际输入互动优先 |
| 舒展 / 飞机返回 | 在动作中段或回收段叠加笑眼与嘴形，随后平滑恢复 |
| nod / celebrate | 与原片段进度同步的笑眼和张嘴程度，避免整段固定表情 |
| attention | 短暂轻微圆嘴，结束后恢复；不表示已获批准 |
| 工作 / 等待 | 较安静的嘴形与正常眨眼；输入、菜单和拖动期间压低夸张表情 |
| 隐藏 / 减少动态效果 | 清除短表情并回到睁眼静态，停止帧请求 |

当前只实现局部几何形变，眼球追踪与语音口型尚未实现。与原 clip 的自然协调仍需持续自用打磨。
开发菜单在同一环境开关下提供表情与近身手势预览；浏览器 `/face-preview.html` 使用同一资产与表演层，
可定格查看六种表情、三个手势及斜侧面，不进入正式产品导航或构建。

## 9. M1 面部与近身回应（同日最新修订）

上一节是 v1 的历史映射，当前 v2 增加专用上眼睑、独立笑眼、眉形和嘴角，共 11 个形变。
语义配方、局部手势时间线、手臂求解分别独立；同一时间线输出姿态和表情，仍只在本地表现层执行。

| 触发 | 当前实现 |
| --- | --- |
| 普通空闲 | 双臂放低、放松嘴形；沿用六套有间隔的待机 |
| 空闲悬停 | 延迟约 0.25 秒开始短挥手与微笑，24 秒冷却；再次移入不连续催促 |
| 工作 | 以现有本地行为段为节奏短暂思考/手靠下巴并专注，随后放松，不持续托腮 |
| 新进入等待 | 原 attention 完成后询问一次，随后保持克制期待，不反复摊手 |
| 点击打开输入 | 保留短笑；输入期间取消近身大手势，关闭后不重播旧手势 |
| 按压、菜单 | 互动优先，手腕阻尼收回；不修改原生窗口拖动实现 |
