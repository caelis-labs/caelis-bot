# 聊天头像动效评估

2026-09-22，评估阶段，尚未实现动态头像。

## 结论

推荐后续制作轻量的分层 2D 头像，用后端状态驱动眼神、眨眼和小幅头部姿态。
本轮先交付静态头像与 Loading 圆点，不采用整张 PNG 固定周期左右倾斜的试验。

参考用户提供的 Chat《调研Grok头像实现》，并核对
[Grok Bot 官方设计说明](https://x.ai/news/designing-grok-bot)。官方确认头像承担身份和
工作状态表达，并将执行详情按需展示。Chat 中的精确几何数量、采样点数、弹簧参数与
内部状态表来自逆向研究，本轮未独立审计，不能当作官方接口或本项目实现约束。

## 当前条件与方案取舍

当前聊天头像为单张 `frontend/public/icons/caelis-avatar.png`，约 26 KiB，显示为 32 pt。
它没有独立的瞳孔、眼睑、头发或脸部图层。整张平移/旋转容易实现，但无法产生独立
视线与表情，不适合作为最终头像系统。

| 方案 | 能力与成本 | 判断 |
| --- | --- | --- |
| 整张 PNG 做位移/旋转 | 无需新增资产；只能摇摆贴图 | 暂不采用 |
| 分层 2D 头像 + 轻量状态调度 | 可独立控制眼神、眨眼、头部；需要重新制作头像成品 | 推荐先做小尺寸样品 |
| 私库离线渲染多朝向/表情图集 | 可复用 3D 人设，客户端很轻；转向连续性受帧数影响 | 分层制作成本较高时的备选 |
| 聊天窗口实时加载 3D 头像 | 可复用已有表情与姿态代码；当前整模约 6.4 MiB，需加载 Three.js 与 WebGL | 暂不采用整模；是否值得独立头部资源须另行测量 |

## 推荐的最小范围

- 保留 Caelis 的粉发、纸飞机和脸部识别特征。先验证 32/40/64 pt 下的可读性，再定
  图层数量；小尺寸头像不必复刻所有头发与服装细节。
- 从静止、工作中、等待确认、异常、完成五类视觉语义开始。语义来自后端能力与
  连接状态；头像运动不能推断真实“思考进度”，不能代替审批、断线或错误信息。
- 工作中只做低频眨眼、短暂看向侧上方等局部变化。采用有界的目标变化与阻尼过渡，
  各行为错开时间，避免一个固定循环同时驱动全头像。
- 仅当前活动消息的头像运行；历史消息静止。窗口隐藏、头像离开可视区时停止更新；
  减少动态效果时使用静态头像。调度器只用于本地表现，不调用模型、不发起后台任务。
- 表现明确之前，继续保留气泡中的圆点；不让用户仅凭细微眼神判断任务是否仍在运行。
- 身份资产和状态调度分开，但不引入 Bot roster、模型身份头像或新的对话入口。
  更换角色不改变现有的长期 Bot 身份。

## 交付边界与验收

分层工程、原图与离线渲染工具仍放在 private `caelis-bot-assets`。公开产品只接收
版本化成品与必要的图层/锚点描述，沿用独立角色授权和哈希校验。新增成品格式前需要
显式扩展公共资产合同及校验器；现有单 PNG 继续作为兼容和加载失败的回退。

先用一个头像做原型，验收小尺寸识别、眨眼不破坏星形高光、转向不露出眼部底图、
浅深色下的边缘、状态切换、减少动态效果与隐藏后零动画更新。测量额外加载时间、
资源体积和后台开销，再决定是否替换默认头像。此次没有测得可承诺的性能数值。
