# 产品约束

## 定位

Caelis Bot 是面向广大普通非技术用户、具有持续身份的常驻个人桌面助手。
Agent 驱动执行，用户表达意图并在关键时刻作出决定。桌面角色是可交互的身体，负责
存在感、情境表达与唤起；长期发展为能结合可信桌面上下文观察、转向、靠近、提醒和交付的助手。
3D 模型、聊天与状态动画只是基础，不以「另一个桌面 pet」作为产品终点。

发展顺序与竞争力假设见[产品发展路线](roadmap.md)。近期先建立 Desktop/Dock/ActiveWindow
轻量概念、基础交互/动作调度与独立道具，和可用性收尾相邻推进；复杂桌面理解、SDK/市场后置。
早期优先开发者持续自用和有辨识度的演示，不要求先证明普通用户长期留存。
基础桌面快照、六套本地待机与独立飞机已接入首个实现切面；整体表现力、自用与演示验收仍在进行，
更深的空间理解及任务/窗口关联尚未实现，不能将路线目标整体作为现有功能宣传。
普通用户定位、同一 Bot 身份、按需唤醒和轻量界面不因引入具身行为而改变。

对外名称固定为 **Caelis Bot**，代码仓库为 `caelis-bot`；`livebot` 仅是讨论中的例名。
“小爱”仅指当前默认的桌面建模形象，不作为产品或助手品牌；欢迎、引导和通用文案使用 Caelis Bot。

Bot 是用户与专业工作之间的常驻秘书。简单日常任务直接处理；代码、调研、分析和制品制作
默认委派到有独立工作目录的内部任务，负责协调、核对和汇报，用户不必另说“创建 Thread”。
任务调度不等于执行授权，具体操作保留原生审批。工作目录与任务句柄不成为默认导航。
桌宠脚边提供收起的任务气泡：悬停显示原始任务 prompt，点击在外部终端观察同一工作。
不增加任务分类或会话控制台；当前入口先支持 Codex。实现范围与权限边界见[任务委派](task-delegation.md)。

## 最终桌面形态

默认常驻 macOS 状态栏（menu bar），同时在桌面显示一个独立的小宠物。
宠物没有普通应用的标题栏、大块背景或占据前台的主窗口；支持拖动、等比调整大小，
并记住位置、比例和显示偏好。当前集中完成 macOS 版本并完整发行；接口保留未来
Windows 扩展能力，Windows 实现须在 macOS 完整发行后启动。Linux 暂不列入计划。具体边界以[跨平台基线](platform-baseline.md)为准。

角色右键只保留“对话”和“隐藏”；状态栏菜单提供“对话”、显示/隐藏、设置、检查更新与明确退出。
双击宠物打开聊天窗口，并将已打开或最小化的设置窗口一起唤回前台，设置置于聊天之上；不重新打开用户已关闭的设置。空闲时单击宠物切换输入胶囊的展开/收起；工作中打开聊天，待审批时展开消息气泡。胶囊展开在其下方，靠近底部时翻到上方，左右边缘自动避让。
输入使用 Enter 发送、Shift+Enter 换行；确认输入法候选不触发发送。多行时有限增高并可滚动。
输入框左侧为朴素的“+”，仅用于附件与可用插件引用，不混入设置或连接状态说明。
不放独立的关闭按钮，点击外部收起。低频配置集中到一个独立设置窗口：常规、外观、
运行时与模型、权限、存储、诊断、关于。窗口默认 960×680，最小 760×540；配置使用
左标签、右控件的分组行，补充说明按需展开，权限范围与错误仍直接可见。角色大小保留 65%–160% 连续等比滑杆，
直接在设置窗口预览并保存，不跳转到角色位置。
右键不重复提供打开输入框动作。应用、状态栏和聊天头像沿用同一 Caelis 角色设计；
应用图标使用饱满的圆角底板构图，状态栏和聊天头像保留透明背景。
菜单在外部点击、切换应用或桌面时收起，不吞掉原点击；明确退出项显示为“退出”。
发送收到后端接受回执后立即收起输入；拒绝或发送结果未知时保留草稿，不自动重发。
实时消息显示为角色上方的独立非激活聊天气泡，只呈现当前请求的最新助手输出和必要生命周期状态。
气泡不显示角色名称或独立状态标题；消息正文与右侧横排操作按钮组成紧凑的一行区域。
靠近顶部时气泡侧向避让；拖动期间暂时收起，松手后重新锚定，不逐帧追赶角色。
气泡运行中可以停止，完成后用 ✓ 收起当前结果；主体点击打开聊天。
审批在消息气泡内按需展开，显示动作、对象、授权范围与明确选项；不再开下方的另一套审批面板。
一次性决定优先；长期/规则授权放入二级展开。提交后等待原生确认，外部点击只折叠。
输入胶囊仅在空闲时发送新 prompt，不承载结果或审批。全局快捷键直接打开聊天窗口、
聚焦输入区，忙碌或未连接时保留草稿并遵循聊天原有的发送/审批限制。
单击、双击和拖动由系统独立识别：双击直接唤回窗口，不先执行单击；单击在系统排除双击后唤起，遵循用户的双击速度设置。默认 Ctrl+Shift+Space
切换聊天窗口的显示/隐藏；隐藏、被遮挡、处于后台或最小化时唤回并聚焦输入区，
只有聊天在前台时再次按下才隐藏。聊天或设置打开期间（包括后台和最小化）显示 Dock 图标，
点击 Dock 唤回仍然打开的窗口，不重新打开已关闭的设置。红色关闭按钮和 Cmd+W 关闭对应页面，
所有常规窗口关闭后恢复菜单栏常驻；桌宠、提醒和工作继续运行。
附着的文件选择对话框保持可达，角色隐藏时仍可使用快捷键；设置支持录入其他组合、关闭、恢复默认和试用。
显式打开或唤回聊天时定位到最新消息；输入区高度或窗口尺寸变化时继续贴底，手动向上翻阅后保留阅读位置。
跨平台偏好使用 Ctrl+Shift+Space，目前只有 macOS 原生注册经过实现。
快捷键冲突不覆盖旧设置。聊天详情随窗口扩展，不设主内容最大宽度。
独立聊天窗口是可选的 IM 式入口：用户/助手消息、发送/补充、结果和必要审批/停止；
默认不展示工具流水，不提供“新会话”。全部界面及原生窗口跟随系统明暗，深色以中性灰为底，
不使用绿色大面积背景。聊天仅保留 macOS 原生标题栏；等待回复时，在消息流中显示
静态角色头像和动态圆点，输出正文后让位。审批、自动审查和停止中保留明确反馈。
聊天输入框右侧共用发送/停止按钮：运行中草稿为空时显示方块，有正文或附件时显示
发送箭头，是否可发送仍由后端能力决定；空输入框按 Enter 不会停止任务。
快捷输入、消息气泡及设置侧栏在 macOS 26+ 使用原生 Liquid Glass；旧系统回退到
原生毛玻璃，减少透明度或增强对比度时使用实色。设置正文和完整聊天保持清晰的实色背景。
文字可读性优先：快捷输入和消息气泡共用 Regular 材质与轻薄阅读底色，正文保持不透明，
避免背景文字干扰；消息气泡不为追求激活态材质而抢夺输入焦点。
聊天中助手消息左对齐、用户消息右对齐，两者都有气泡；助手气泡旁显示本地角色头像。
应用图标与头像使用用户提供的纸飞机小女孩设计。复制使用双矩形图标，在气泡内部右上角仅悬停或
键盘聚焦时出现，成功后显示勾选反馈，不占用常驻行或改变布局。
普通使用不依赖常开主窗口，不用完整聊天工作台包围角色。

宠物空闲时不抢输入焦点；用户主动打开输入框时才取得输入焦点。隐藏宠物、
收起面板、取消任务、退出应用是不同动作，必须分别定义行为。
宠物随同一显示器上的 macOS 桌面（Space）与原生全屏应用保持可用，不抢焦点；
切换时收起输入胶囊，位置和比例保持。主动隐藏后不能因切换桌面重新出现。
物理外接显示器的迁移/混合 DPI/拔屏恢复独立验收，不与 Space 切换混为一项。

用户提供的前台窗口截图是需替换的准备外壳；第二张图仅参考“角色 + 紧凑入口”的
布局，不规定角色风格、2D 技术或首版语音能力，详见[资料记录](references.md)。

## 长期身份与按需唤醒

2026-09-23 架构方向：Bot 自己持有身份、私有笔记与记忆、任务协调、提醒和桌面工具，
通过通用执行接口接入各 Runtime；Caelis 保持 Core 定位。私人长期记忆列入下一版核心闭环，
不以某个工作区或执行会话作为身份。同一 Bot 的个人资料、笔记和长期记忆跨 Runtime 共享，
各 Runtime 的原生会话、凭据、权限和在途工作仍分别绑定。具体边界与迁移见
[Bot 产品宿主规划](bot-platform-architecture.md)。身份、任务协调、提醒与工具已统一到本应用；
Notebook/Memory 已由应用持有，用户直接编辑 Markdown，Bot 通过专属 skill 和普通文件工具维护，见
[个人空间](personal-memory.md)。Caelis 新通用协议已完成隔离真实模型验收，具体覆盖与剩余的
GUI/发行验证见 [正式版联调报告](caelis-release-acceptance.md)。

长期连续性收敛为长 Session/Compact、recall/remember 与一本结构清晰的 Notebook。
初始化时仅出现一次 Bot 名字（必填）和描述（可选）表单，提交为可见的普通用户消息，由 Bot 更新 MEMORY.md；
不另存配置副本，不提升为系统指令，未投递或未写入成功不显示已修改。
Notebook 仅包含系统生成的 INDEX.md、用户与 Bot 维护的核心 MEMORY.md，以及 YYYY/MM/DD/
日期笔记。用户直接编辑 Markdown，Bot 使用 Runtime 文件工具；不提供专用笔记管理 UI 或 CRUD 工具。
不另设 SOUL/USER 文件、核心认知层或同步的用户画像。独立资料页与专用笔记 CRUD 工具已退出；
具体目录、读写习惯、迁移和验收见[笔记方向](personal-memory.md)。

Bot 是持续存在的助手，用户不管理 Session 或工作区。内部可以管理多个工作 Thread，
使用后端通信工具协作，最终仍由同一个 Bot 对用户说话。
初版仅由用户 prompt 与用户设定的定时任务激活，不长期空跑模型。
定时任务依赖应用常驻，隐藏照常执行，睡眠错过的同类提醒合并，明确退出后暂停。
Agent 通过受控接口驱动提醒与角色动作，动作不产生执行授权。
完整职责与边界见 [Bot 设计](bot-design.md)。

## 用户入口

默认只提供状态栏、角色与一个紧凑的唤起入口。按需展开：

- 对话和必要的工作结果；
- 上传或拖入附件；
- 有上下文、明确动作对象与选项的审批；
- 当前工作确实需要的插件、连接器安装与授权；
- 少量用户可理解的偏好，如宠物大小、显示行为，以及已有能力的声音/角色选项。

审批既能提醒用户，也必须提供足以作出决定的信息。轻量不意味着省略关键信息。
点击、抚摸、拖拽角色不能隐式通过审批。
审批需要较多内容时可扩展面板，提供滚动、完整对象和后果说明，不强塞进小气泡。
语音、自动启动等可按实际需求迭代；无实现的功能不放置虚假按钮。

## 不作为默认产品入口

不展示 Session/thread ID 或会话管理器、工作区树、模型参数、协议配置、终端面板、
Agent 拓扑与开发者仪表盘。后台可能拥有多个任务和对话，它们不自动变为 UI 标签页。
用户恢复未完成工作时，使用需求和结果的语言，不要求其选择技术 Session。

完整 TUI/IDE/App 的重实现不属于本产品。用户不必学习开发工具概念才能获得帮助。

## 能力范围

协议可以表达完整的 Agent 能力，包括工具执行、审批、附件、任务、插件和连接器。
Codex App Server 和 Caelis Control Host 通过独立适配器接入；能力按各自原生合同协商。
Caelis 的官方安装、检测、更新及服务管理入口保留，不打包运行时。执行路径使用通用应用协议，
按能力协商开放；不恢复旧 Bot Mode，不会自动回退到另一 Runtime 或清理旧数据。
历史能力和验证限制见 [Caelis 接入](caelis-integration.md)。
Codex 使用用户本机安装，通过标准 App Server 发现、初始化与账户接口连接；
应用不携带、不静默安装 Codex 运行时，也不接管 Codex App 自己的进程或任务。
若已有标准 App Server 本地入口，直接握手，不要求安装 CLI；否则再发现 CLI。
标准入口不可用或握手失败时自动回退到 CLI。设置中的“运行时与模型”默认自动发现；
选择 Codex 时也可手动指定 CLI 完整路径，检测通过后才保存，并在后续启动复用。
仅“Codex App 已打开”不保证它开放可连接入口，不通过启动 App 或修改其配置来伪造支持。
不限制用户 CLI 的具体发行版本，兼容所需 App Server 协议的安装均可接入。未找到安装或
所需协议接口不兼容时，提供安装说明与重新检测；登录成功后恢复原有 Bot 对话。

系统通知位于设置的“常规”，由用户主动开启。隐藏桌宠时仍可收到到期提醒、
必要审批和工作完成通知；点击通知只打开聊天，不隐式批准或重新执行工作。
通知受系统权限与专注模式影响，不强行显示桌宠或抢焦点。

可恢复的连接重试、未使用的附属通知和可选 MCP 启动失败不进入聊天或角色气泡，
也不把仍在执行的工作标为失败。需要用户决定、实际任务失败或执行状态无法确认时
才显示必要提示。原生宿主保存有限期、有限大小的私有诊断日志，记录脱敏原因与
可回溯的事件标识；不记录完整对话、工具参数、凭据或环境变量值。

## 角色表现与 3D 价值

火柴人已完成基础工作流验证。当前采用用户提供的 Caelis 花裙小女孩人设，复用小爱迭代中
已精修的脸眼、头发和动作骨架，主要重建衣服与饰品。五段动作、隐藏暂停和动态点击
区域由宿主负责。用户仍反馈动作存在感弱、未体现 3D 优势；资产接入通过不代表表现力合格。
近期将动作可读性、情境注视/转身、六套待机（初始基线四静两动）、鼠标交互和工作响应列为产品能力，
并支持纸飞机这样的独立道具。轻量桌面概念与这些能力一起建立，随后扩展角色行走与任务空间关联。
它们不能继续笼统归入后置的美术优化，也不以增加面数或持续大幅动作代替。

在日常显示尺寸下，用户应看得懂角色的朝向、姿态和反应原因；通过骨骼与局部动作组合体现
3D 的价值。允许根据鼠标、Dock/前台窗口等环境作出反应，无需绑定到工作任务；不冒充 Agent
正在操作某个窗口。交互矩阵和随机待机/道具生命周期见[桌面概念与交互基线](desktop-behavior.md)。手动拖动和输入优先；
隐藏、减少动态效果仍生效，角色不得为了表演抢焦点或反复催促审批。

当前来源、制作边界与美术限制见[成品合同](character-assets.md)，历史小爱源及记录保留。
后续优先使用新的 Caelis 人设，脸眼暂保持现版；旧角色不进入生产包。新增骨架/片段需求先对齐[动作约定](character-actions.md)。
设置的“外观”已支持本地内容包导入、完整角色/服装变体切换及独立 PNG 头像；
内置资源仍作为回退，外观选择不改变助手身份、对话与 Runtime。应用本体保持免费开源。
社区制作流程见[内容包开发](content-packs.md)。复杂动画库、自动重定向与独立蒙皮换装尚未开放。
早期发行提供预置内容与第三方包导入；基础表现力独立推进。

正式版使用 Sparkle，每天自动检查公开签名更新清单，也可从状态栏或设置主动检查。
用户可以关闭自动检查；发现新版后由用户确认下载与安装，应用负责签名验证、替换与重启。
对话、独立工作、待审批或结果未知的操作未结束时延后重启，不为更新取消工作。
更新保留身份、对话、笔记与设置。开发/预览构建保留公开发布页手动下载路径；
R2 仅保留最新正式版。首次接入以前的版本仍须手动安装一次，不能声称旧版已支持自动更新。

## 模型与权限偏好

“运行时与模型”集中管理运行时、模型与连接。顶部显示当前 Runtime，“更换”进入安装、
检测与切换；程序位置和更新收在“高级”。运行时切换需要重启，各自保留对话与设置。

“模型与 Team”区分 Bot 对话模型与 Caelis 工作主模型。工作主模型与本机 TUI `/model`
共用；Agent team 使用 `/team` 的角色、模型能力和方案，支持绑定、恢复默认、自定义角色、
保存和应用方案。`self` 跟随工作会话主模型，不提供单独编辑。未绑定角色保留原生默认行为。
每个编辑面板单独保存；配置冲突时读取最新状态并核对草稿，结果未知时先刷新核对，不自动重试。
推理强度和速度选项来自 Runtime，不支持的档位不可保存。模型参数只出现在设置中。

“连接”按模型服务和外部 Agent 分组，标明主模型、Bot 和角色的用途。模型服务可以使用
账号授权或 API Key；外部 Agent 从 Caelis 内置目录选择，也可输入自定义 ACP 启动命令。
安装路径和来源、Agent 认证方式及模型均来自 Runtime。需要交互式终端的认证提示先使用 TUI。
浏览器授权显示原生登录链接、设备代码或一次性输入；取消不会自动再次发送连接命令。
凭据由 Caelis 保存，Bot 不持久化密钥或授权码。外部 Agent 按整个连接断开，不卸载程序。

新建工作默认沿用 Runtime 的模型、推理强度与速度；只有 Runtime 未配置模型才回退到 Bot
设置，读取失败不视为未配置。高级中的“独立工作模型”保留显式覆盖入口，只影响新任务。
已有任务续接和恢复仍保留原模型；工作目录、权限和审批使用既有策略。

“权限”单独管理审批方式，保存时读取最新执行设置，避免覆盖另一面板的模型更改。
自动审查为默认；还可选择用户确认、只读命令沙箱或完全访问。权限更改遵循执行中的
准入检查；命令沙箱不替代连接器和工具自身的权限管理。
