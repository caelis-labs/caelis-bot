# Issue draft: Windows 11 x64 first native Caelis Bot product

## Source and scope

- Base: `origin/main` at `cf9071982563eddb9926f1ba7a09062148f9ad26` (`v0.8.0`).
- Foundation branch: `feat/platform-foundation`. PR/head and final CI results are filled in at handoff.
- Complete the first Windows 11 x64 product in the existing long-lived Bot identity. Do not add a dashboard, workspace/session navigation, Windows arm64 or Linux GUI. Exact macOS visual parity is not a release gate.
- A native Windows runner, cross-compiled binary, staged Desktop World package and synthetic fixtures are preparation evidence. They do not certify Windows GUI, OS permissions, installation, signing or public release.

## Foundation available from the Mac stage

- `internal/desktop/assembly.go` owns the one `app.Application` and binds the desktop/backend services. `runtime_darwin.go` keeps native windows, tray, AppKit lifecycle, relaunch and updater. Windows must call the shared assembly once; do not copy the Mac runtime or create a second product core.
- `internal/app.Host` is the small effect port for URLs, files, trash, notifications, observation and Desktop World. `internal/desktop/feature_capabilities.go` and `frontend/src/capabilities.ts` distinguish `supported`, `available`, saved `enabled`, and OS `permission`; user choices and OS grants stay separate.
- `internal/secretstore.Store` is consumed by Telegram and SSH machine profiles. Native Mac adapters still use the existing Keychain scopes. Implement Windows Credential Manager per consumer and keep secrets out of renderer state and logs.
- `internal/localipc.Endpoint` names transport. Darwin and Linux headless use a private Unix socket; Windows `Listen/Dial` deliberately return unsupported. `internal/localstate` uses a flushed temporary file and Windows `MoveFileEx` write-through replacement for durable care/receipt state; native ACL enforcement remains a Windows acceptance gate. `internal/taskterminal/arguments.go` has bounded argv for local task observation; the POSIX script/receipt implementation is excluded on Windows and its stub fails explicitly.
- `internal/desktop/data_directory_windows.go` selects `%LOCALAPPDATA%/Caelis Bot` or `Caelis Bot Dev`; an explicit absolute `CAELIS_BOT_DATA_DIR` remains the isolated test profile. The final Windows preview identity should have its own package and data root.
- `resources/desktop-world/release.json` pins rc.3 at revision `43172bb1f3dd26b90a88c346bc9978cbabab5785` for Darwin arm64 and Windows amd64. The official Windows zip SHA-256 is `c847a4b5068cbe49bcc7527fbd546584e16989e8138a365116128c0b1f850a63`; `script/stage-desktop-world-windows.ps1` checks archive, binary, manifest, source and licenses. No Windows desktop action is claimed from that packaging check.
- `.github/workflows/ci.yml` routes shared/frontend/protocol/dependency changes to macOS and native Windows, platform-only edits to their own runner plus shared sanity, unknown paths to all. `product` remains fail closed; Linux headless checks remain. Windows currently builds an unsupported bootstrap, deliberately.
- `script/publication.mjs` uses `(tag, os, arch, channel)` publication receipts, exact source SHA and asset digests. It reconciles unknown uploads by downloading existing bytes and never clobbers a published asset. `script/windows-acceptance.mjs` requires an exact signed MSIX and a channel-namespaced `Caelis-Bot-X.Y.Z-windows-amd64-{channel}.acceptance.json` before a Windows publication. The macOS release remains independent and its old signed R2 paths continue to update. No Windows package/feed is published by this foundation PR.

## Ordered implementation tasks and acceptance

1. **Native shell and identity.** Add `runtime_windows.go` with one Wails App, tray menu and independently visible minimum pet. Preserve on-demand bubble, conversation, history, settings and approval windows and file drops. Close/hide must leave Bot work running; tray Quit and runtime restart must follow the single shared core shutdown order. Use `Caelis Bot Dev` and release identity separately, and add a distinct preview package/data identity. Verify on Windows 11 with real WebView2, a physical pointer and actual windows; record tray, pet drag/resize, bubble, close/reopen, display scaling, Unicode user profile and sleep/restart evidence. Do not clone AppKit-only options.
2. **Private local IPC and credentials.** Implement `internal/localipc` Named Pipe listener/dialer with a per-launch unguessable name, current-user SID DACL, rejection of remote clients, same-user/peer process identity verification and original token/framing limits. Implement Credential Manager adapters for Telegram and SSH with per-product service/account scopes, restricted access, safe missing/locked behavior and no prompt on passive reads. Test a second user/access-denied client, stale endpoint and clean close on the real OS. Do not relax the existing unknown receipt or approval fences.
3. **Owned Runtime and process lifecycle.** Implement Codex App Server discovery through PATH/PATHEXT and npm `.cmd` shims, standard handshake, connection reuse/reattach and exact original receipt recovery. Preserve native run/item IDs and auto_review policy. Use Job Objects for the owned App Server subtree, but keep independently delegated Workers, remote tasks and external terminal instances outside the Bot-owned kill scope. Verify exit, crash, reconnect, runtime switch and restart with live local Codex. Never infer completion from a window close or generated prose.
4. **Task terminal and OS effects.** Implement Windows native terminal open/observe/confirm/revoke using `TerminalArguments`; every explicit click gets a unique receipt, an uncertain launch stays associated with that original receipt, and an existing owned terminal instance is reused. Resolve command paths and Unicode args without shell interpolation; test `PATH`, `PATHEXT`, npm shims and apostrophe/space/CJK paths. Add Windows file picker, reveal/trash, clipboard, notifications and restart effects to the corresponding `app.Host` callbacks. Verify attachment bytes and cancellation, not only dialog delivery.
5. **Desktop World and product capabilities.** Stage the pinned rc.3 Windows helper with its MPL source/licenses. Implement the Windows `desktopcontrol` host path and actual per-turn/per-App authority. Test bounded observation, one approved input, original requestId readback, rejected/unknown results without replay and target-change failure on Windows 11. Surface `supported/available/enabled/permission` dynamically in setup/settings; permission reads must not trigger grants. Complete Runtime, Memory/Notebook, tasks, Telegram protocol, approval and attachment product flows in real Windows windows. Add direct screenshots/interaction receipts for English and Chinese as relevant.
6. **Packaging, provisioning and update choice.** Use **user-scoped MSIX** as the first Windows installer, using the pinned Wails v3 MSIX tooling already in the dependency tree; do not add a second installer framework. Keep user data in `%LOCALAPPDATA%` outside package replacement. Provision/verify the WebView2 Evergreen runtime with a pinned bootstrapper or explicit prerequisite, including offline/missing-runtime behavior. Map semantic tag to a monotonic four-part package version without changing the canonical tag/changelog. Clean install, upgrade, uninstall and reinstall must preserve user data unless the user explicitly chooses deletion; Dev/preview/stable packages must not overwrite each other's data or identity. First Windows updates are **manual, signed MSIX downloads**, not an unverified auto-installer.
7. **Windows signing, independent publication and feeds.** Build without secrets first; sign only the already built MSIX with a Windows code-signing certificate and trusted timestamp in a protected Windows release environment. Verify Authenticode, certificate chain, timestamp, MSIX publisher/identity, package hash and the actual installed package. Generate `Caelis-Bot-X.Y.Z-windows-amd64-{channel}.acceptance.json` with exact tag/source/package digest and every required native check in `script/windows-acceptance.mjs`; only then call `script/publication.mjs` for `windows-amd64` and its channel. The first qualified platform may publish the shared GitHub draft; later platforms append immutable namespaced assets. Windows stable and preview each get their own signed `caelis-bot/feeds/windows/amd64/{channel}/latest.json` and versioned immutable objects, with separate R2 concurrency/ownership and rollback tests. Windows preview on a stable source must not change a Mac stable release's global prerelease status. Preserve Mac `caelis-bot/appcast.xml`, `latest.json`, signature and existing Sparkle behavior. Never use GitHub global Latest as a platform selection oracle.
8. **Final release acceptance.** On Windows 11 x64 run native product flows, installation and update scenarios against exact built bytes. Test a cache holding an older feed, a late Windows platform, a single-platform failure, retry after unknown upload, concurrent publishers, signing/source mismatch and channel/OS prune boundaries. Gate publication on the installed signed MSIX and manifest, not only CI. Create a separate Windows release workflow only when it can produce and verify those artifacts; no placeholder assets or feed changes before then.

the Windows CI runner and helper staging cannot substitute for these Windows checks.
