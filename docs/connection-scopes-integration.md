For **new Caelis Bot conversations and natural handoffs**, auto-review creates `workspace-write + auto-review + Guardian`. Full access creates `danger-full-access + auto-review + execution_approval=never + Guardian`. `never` bypasses Runtime execution review for trusted required Application callbacks after identity and argument checks. It does not grant a callback's own effect, background work, account access, Computer Use, MCP access, or macOS TCC. `application-execution-approval-never-v1` and the scoped Host connection's `allow_unreviewed_application_execution=true` must both be observed before a new full-access request. The exact permissions and Reviewer are journaled before POST and compared with the returned immutable binding. An existing bound Session keeps its original profile regardless of future preference.

For **new Caelis Workers**, the selected auto/full preference becomes an immutable `CreateWorkerRequest.permissions` pair: `workspace-write/auto-review` or `danger-full-access/auto-review`. The adapter requires `worker-creation-permissions-v1`, and full also requires the independent `allow_worker_full_access=true` Host grant. It persists the pair in the task start, checks the creation receipt when present and the native Session state's `worker_permissions` before any prompt, including after a crash. It never uses `POST /sessions/{id}/configuration/session-mode` to change Worker approval. An old pending Worker with no explicit pair continues under its original Host default and receipt.

The Bot registration request still adds neither grant. Core registration is immutable; a prior connection defaults both grants to false, and renew does not upgrade it. The new settings action asks the person to confirm **Bot** or **Worker** full access separately. Only then does the native Caelis adapter use its protected Host credential for `application-connection-grant-updates-v1`: it targets the existing Connection ID with an exact-state CAS, persists the original operation before POST, validates its immutable receipt, then reads the same connection through both Host and Application credentials. It changes only the selected grant. The Worker settings interface is fixed to the Worker scope, and the Host credential never enters a Worker creation request or model-visible context. The UI saves the corresponding future preference after native success and a second options/settings readback. Bot full access closes its confirmation only after that authoritative readback says `full-access`; an `auto` readback or read error leaves the error visible and confirmation pending without issuing another grant. A lost response retains the original operation for idempotent retry; a Host/identity/receipt/readback mismatch refuses the preference save. A prior receipt alone cannot establish current authorization. Old Hosts give an upgrade message; their schema-3 Store is never auto-migrated or downgraded by Bot. Neither old Session nor existing task authority is rewritten, and the App does not alter a real Host during fixture tests. This Bot adapter checks the canonical native Worker pin before the original prompt and preserves the original receipt if a mismatch is observed. A pin conflict is reported as an actionable error, never repaired by editing a receipt or creating a replacement task.
